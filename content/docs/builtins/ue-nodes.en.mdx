description: The 27 UE.* names 1.x implemented itself and their argument lists, the bases of the two transform builtins, the three special-cased names, and the Properties declaration form.

The `UE.` namespace is how DreamShaderLang creates Unreal material nodes. Twenty-seven of its names are
ones 1.x **implemented itself**, each with a fixed argument list; three more —
`UE.StaticSwitchParameter`, `UE.CollectionParam` and `UE.SceneTexture` — are special-cased.

<Since v="2.0.0" /> Every `UE.` name — these included — is a node of the **builtin catalog**: the
material expression classes of the running engine, read by reflection (`dsc export-catalog` writes it
out). What the 27 names keep is their 1.x argument lists, which the legacy front end applies to a
`.dsm` / `.dsf` / `.dsh` before the binder sees the call. A name this page does not list works just
the same — any engine class is called by its short name (the class name without
`MaterialExpression`), by the rules of [Generic UE.Expression](/en/docs/builtins/ue-expression); a name
the running engine has no class for is `DSH5210`.

How names are matched:

| Part | Rule |
| :-- | :-- |
| `UE.` prefix | exact <Since v="2.0.0" /> — `ue.TexCoord()` reads `ue` as a variable and is `DSH4200` |
| Builtin name | exact; in a 1.x source a name that matches only ignoring case is accepted with the warning `DSH5276` — `UE.texcoord()` is `UE.TexCoord()` |
| Argument names | trimmed, then matched the same way; otherwise exact — `Un_Mirror_U` is not `UnMirrorU` |

Each name is a class of the catalog: its short name, or one of the 1.x aliases the catalog carries —
`TexCoord`, `ObjectPosition`, `CameraVector`, `CameraPosition`, `ReflectionVector`, `ViewportUV`,
`TransformVector`.

## Read these two things before the catalogue

<Callout type="warn">
**An argument a 1.x name did not read is dropped — with a warning now.** For the 27 names in the
[full list](#full-list), the legacy front end keeps the argument list of each entry below and drops
every other argument — an unknown or misspelled name, or a positional argument — with `DSH5254`
<Since v="2.0.0" /> (1.x dropped them without a word). `UE.TexCoord(Indx = 3)` still produces UV channel
0, and says why; `UE.Panner(SpedX = 1)` pans at the node default speed and says so. The only
positional argument kept is position 0 of `UE.TransformVector` and `UE.TransformPosition` (→ `Input`);
`UE.StaticSwitchParameter` reads `True` and `False` at positions 0 and 1. An argument that passes the
filter is bound against the catalog like the argument of any node call.
</Callout>

<Callout type="info">
**Two identical calls are one node**, whichever builtin they are <Since v="2.0.0" />: the IR merges
nodes with the same class, properties and inputs. 1.x merged only the generic and `Substrate.*` calls,
so `UE.TexCoord(Index = 0)` written in five places made five nodes; it makes one now. See
[Node reuse](/en/docs/graph/expressions#node-reuse).
</Callout>

## Synopsis

<Grammar />

<Synopsis>
```c
// expression form, inside Graph
UE.<Name> ( [ <argument> [ , <argument> ] … ] )

<argument> := <arg-name> = <expression>

// declaration form, inside Properties
UE.<Name> [ ( <key> = <value> [ , <key> = <value> ] … ) ] <property-name> ;
```
</Synopsis>

## Output widths

The type of a call is the catalog's — the engine's own description of the class, on the running
engine:

- a masked output is as wide as its mask;
- an unmasked output has the engine's value type, or, where the engine says only "a float", a width
  DreamShader keeps for the class: 1 for `Time`, `PixelDepth`, `SceneDepth`, `ObjectRadius`,
  `TwoSidedSign`, `PerInstanceRandom`, `PerInstanceFadeAmount`; 2 for `TextureCoordinate`, `Panner`; 3
  for `ObjectPositionWS`, `ObjectBounds`, `CameraVectorWS`, `CameraPositionWS`, `ReflectionVectorWS`,
  `VertexNormalWS`, `VertexTangentWS`, `PixelNormalWS`, `Transform`, `TransformPosition`;
- an output the engine does not type at all is as wide as the place it is read into;
- a node with several outputs is read by naming one (`UE.ScreenPosition().ViewportUV`), or used whole
  where its first output — or the value its channel outputs make up (`float4 VC = UE.VertexColor();`) —
  fits exactly. In a 1.x source a node whose first output has no fixed width is read as that output
  (`DSH5287`), and so is any node passed straight to a pin — `UE.TransformPosition(UE.WorldPosition(), …)`
  takes `XYZ`, as 1.x connected it <Since v="2.1.1" /> (2.0.0 – 2.1.0 refused one whose first output
  has a fixed width with `DSH5201`).

None of these builtins produces a texture object, a `MaterialAttributes` value or a Substrate value.

| Alias | Same as | Difference |

## Builtins with arguments

### UE.TexCoord

```c
float2 uv    = UE.TexCoord(Index = 0);
float2 tiled = UE.TexCoord(Index = 0, UTiling = 2.0, VTiling = 2.0);
```

| Argument | Kind | Default | Required |
| :-- | :-- | :-- | :-- |
| `Index` | constant — the property `CoordinateIndex` | node default, UV channel 0 | no |
| `UTiling` | constant | node default | no |
| `VTiling` | constant | node default | no |
| `UnMirrorU` | constant `true` / `false` | node default | no |
| `UnMirrorV` | constant `true` / `false` | node default | no |

`Index` is the catalog's alias of `CoordinateIndex`. `CoordinateIndex` itself is not on the 1.x list,
so in this form it is dropped with `DSH5254`; the [declaration form](#properties-declaration-form) takes
both. A negative `Index` is written through without a diagnostic.

### UE.Time

```c
float t      = UE.Time();
float looped = UE.Time(Period = 2.0, IgnorePause = true);
```

| Argument | Kind | Default | Required |
| :-- | :-- | :-- | :-- |
| `Period` | constant | absent — the node's period override stays off | no |
| `IgnorePause` | constant `true` / `false` — the property `bIgnorePause` | node default | no |

Supplying `Period` also turns on the node's period override: the front end adds
`bOverride_Period = true` to the call. No range check is applied: a negative `Period` is written
through — in the declaration form too <Since v="2.0.0" />.

### UE.Panner

```c
float2 panned = UE.Panner(Coordinate = UE.TexCoord(Index = 0),
                          Time       = UE.Time(),
                          SpeedX     = 0.1,
                          SpeedY     = 0.0);
```

| Argument | Kind | Default | Required |
| :-- | :-- | :-- | :-- |
| `Coordinate` | input pin | unconnected | no |
| `Time` | input pin | unconnected | no |
| `Speed` | input pin | unconnected | no |
| `SpeedX` | constant | node default | no |
| `SpeedY` | constant | node default | no |
| `FractionalPart` | constant `true` / `false` — the property `bFractionalPart` | node default | no |

`ConstCoordinate` is dropped with `DSH5254` in this form; the declaration form passes it through, and
so does the class name: `UE.Expression(Class = "Panner", ConstCoordinate = 1)`.

## Transform builtins

The two builtins that change the basis of a value: `UE.TransformVector` for **directions** and
`UE.TransformPosition` for **points**. Both output `float3`, and both require `Input`, given by name or
at position 0.

A basis is a value of the engine's enum, written without its prefix: `"World"`, or the bare word
`World`. In a `.dss` it is matched exactly. In a 1.x source case, spaces, `_` and `-` are ignored and the
enum's prefix or scope may be written, with the warning `DSH5278`: `"world"`, `" WORLD "` and
`TRANSFORMSOURCE_World` are `World`. A value the enum does not have is `DSH5215`, whose message names the
property that failed — `TransformSourceType` for `Source`, `TransformType` for `Destination`.

<Callout type="warn">
**Always name `Source` and `Destination` in full.** These names read only their 1.x arguments and drop
anything else with `DSH5254`: `UE.TransformVector(V, Src = "World")` uses the default `Source`
(`Tangent`), because the argument is spelled `Src`; a second positional argument —
`UE.TransformVector(V, "World")` — is dropped too, since only position 0 is read. A call with no
`Input`, by name or at position 0, is the warning `DSH5279` and leaves the pin unconnected
<Since v="2.0.0" /> (1.x refused the call).
</Callout>

### UE.TransformVector

Transforms a **direction** between bases. Rotation only — translation is not applied, which is what
makes it the wrong choice for a point.

```c
vec3 worldNormal = UE.TransformVector(LocalNormal, Source = "Tangent", Destination = "World");
```

| Argument | Kind | Default | Required |
| :-- | :-- | :-- | :-- |
| **`Input`** | input pin; may be given at position 0 | — | **yes** |
| `Source` | enum value — the property `TransformSourceType` | `Tangent` (the node's) | no |
| `Destination` | enum value — the property `TransformType` | `World` (the node's) | no |

Both sides take the same six spellings:

| Spelling | `EMaterialVectorCoordTransformSource` | `EMaterialVectorCoordTransform` |
| :-- | :-- | :-- |
| `Tangent` | `TRANSFORMSOURCE_Tangent` | `TRANSFORM_Tangent` |
| `Local` | `TRANSFORMSOURCE_Local` | `TRANSFORM_Local` |
| `World` | `TRANSFORMSOURCE_World` | `TRANSFORM_World` |
| `View` | `TRANSFORMSOURCE_View` | `TRANSFORM_View` |
| `Camera` | `TRANSFORMSOURCE_Camera` | `TRANSFORM_Camera` |
| `Instance` | `TRANSFORMSOURCE_Instance` | `TRANSFORM_Instance` |

A 1.x source may also write `AbsoluteWorld` for `World`, and `Particle` or `InstanceParticle` for
`Instance`, on either side, in any case: the front end writes the engine's name, with the warning
`DSH5278` <Since v="2.1.1" /> (2.0.0 – 2.1.0 refused each with `DSH5215`). The engine's own
`ParticleWorld` value is hidden, and the catalog leaves it out.

### UE.TransformPosition

Transforms a **point** between bases, applying translation.

```c
vec3 viewP = UE.TransformPosition(UE.WorldPosition(),
                                  Source      = "World",
                                  Destination = "TranslatedWorld");
```

| Argument | Kind | Default | Required |
| :-- | :-- | :-- | :-- |
| **`Input`** | input pin; may be given at position 0 | — | **yes** |
| `Source` | enum value — the property `TransformSourceType` | `Local` (the node's) | no |
| `Destination` | enum value — the property `TransformType` | `World`, as in 1.x — not the node's `Local` | no |
| `PeriodicWorldTileSize` | input pin, where the engine's class has it | unconnected | no |
| `FirstPersonInterpolationAlpha` | input pin, where the engine's class has it | unconnected | no |

<Callout type="warn">
**The node's own `Destination` is `Local`.** 1.x wrote `World`, and so does the front end
<Since v="2.1.1" />: a call without `Destination` goes to world space, and
[`dsc migrate`](/en/docs/language-v2/migrate) writes `Destination = World` out, because a `.dss` call
gets the node's `Local`. 2.0.0 – 2.1.0 wrote no default, and such a call was a transform that changed
nothing.
</Callout>

One enum serves both `Source` and `Destination`:

| Spelling | `EMaterialPositionTransformSource` |
| :-- | :-- |
| `Local` | `TRANSFORMPOSSOURCE_Local` |
| `World` | `TRANSFORMPOSSOURCE_World` |
| `PeriodicWorld` | `TRANSFORMPOSSOURCE_PeriodicWorld` — where the engine's enum has it |
| `TranslatedWorld` | `TRANSFORMPOSSOURCE_TranslatedWorld` |
| `FirstPersonTranslatedWorld` | `TRANSFORMPOSSOURCE_FirstPersonTranslatedWorld` — where the engine's enum has it |
| `View` | `TRANSFORMPOSSOURCE_View` |
| `Camera` | `TRANSFORMPOSSOURCE_Camera` |
| `Instance` | `TRANSFORMPOSSOURCE_Instance` |

A 1.x source may also write `AbsoluteWorld` (`World`), `CameraRelativeWorld` (`TranslatedWorld`),
`FirstPerson` (`FirstPersonTranslatedWorld`), `Particle` and `InstanceParticle` (`Instance`), in any
case: the front end writes the engine's name, with the warning `DSH5278` <Since v="2.1.1" />
(2.0.0 – 2.1.0 refused each with `DSH5215`). The engine marks `FirstPersonTranslatedWorld` as no valid
*Source*; DreamShader does not check that.

<Callout type="warn">
**A basis the running engine lacks is reported as an unknown value, not as a version error.** On an
engine whose enum has no `PeriodicWorld`, `UE.TransformPosition(P, Destination = "PeriodicWorld")` is
`DSH5215` — the code a typo gets.

**The two optional pins follow the engine, both the same way.** On an engine whose class lacks
`PeriodicWorldTileSize` or `FirstPersonInterpolationAlpha`, the argument is no pin of the node: a 1.x
source keeps it with the info `DSH5291`, and building the node fails with `DSH8212` <Since v="2.0.0" />
(1.x dropped the first silently and refused the second with an error of its own). To keep one source
building across engine versions, guard the argument with `#if DS_ENGINE_MINOR >= …` — see
[Preprocessor](/en/docs/language/lexical#preprocessor).
</Callout>

## Special-cased builtins

`UE.StaticSwitchParameter` and `UE.SceneTexture` are rewritten by the legacy front end into
`UE.Expression` calls before the binder sees them. `UE.CollectionParam` is not: the catalog knows it as
a second name of `UE.CollectionParameter`.

### UE.StaticSwitchParameter

<Since v="1.2.3" />

Creates a static switch that appears in the material instance editor, so an artist can flip branches
without touching source.

```c
vec3 color = UE.StaticSwitchParameter(Name        = "UseDetail",
                                      True        = detailColor,
                                      False       = baseColor,
                                      Default     = true,
                                      Group       = "Switches",
                                      Description = "Choose the detail branch");
```

| Argument | Aliases | Kind | Default | Required |
| :-- | :-- | :-- | :-- | :-- |
| **`Name`** | `ParameterName` | a quoted string or a word, non-blank after trimming | — | **yes** |
| **`True`** | `A`, position 0 | value | — | **yes** |
| **`False`** | `B`, position 1 | value | — | **yes** |
| `Default` | `DefaultValue` | `true` / `false` | `false` | no |
| `Group` | — | a quoted string or a word | none | no |
| `Description` | — | a quoted string or a word | none | no |
| `SortPriority` | — | whole number | node default | no |

The call becomes

```c
UE.Expression(Class = "StaticSwitchParameter", ParameterName = …, DefaultValue = …, Group = …,
              Desc = …, SortPriority = …, A = <True>, B = <False>)
```

and any other argument is dropped with `DSH5254`.

The output follows the branches: it is as wide as the wider numeric branch, or the Substrate or
`MaterialAttributes` value a branch carries. The two branches are **not** compared with each other
<Since v="2.0.0" />; a texture in either is `DSH5214`. The parameter is registered with an editor-only
static-switch value on the generated material — or material function — so it appears in the instance
editor. Two calls with the same arguments are one node.

<Callout type="info">
`Group` and `Description` are written to the node's `Group` and `Desc` properties; a value that is
neither a quoted string nor a word is `DSH5224` <Since v="2.0.0" /> (1.x discarded it without a
diagnostic).
</Callout>

### UE.CollectionParam

<Since v="1.2.3" />

Reads a scalar or vector parameter out of a `UMaterialParameterCollection`.

```c
float wind = UE.CollectionParam(Collection = Path(Game, "Collections/MPC_Wind"),
                                Parameter  = "WindStrength");
```

`UE.CollectionParam` and the engine's name, `UE.CollectionParameter`, are one class, in a `Graph` body
and in the [declaration form](#properties-declaration-form) alike <Since v="2.1.1" />. 2.0.0 – 2.1.0
refused `UE.CollectionParam` in a `Graph` body with `DSH5210`.

| Argument | Aliases | Kind | Default | Required |
| :-- | :-- | :-- | :-- | :-- |
| **`Collection`** | `Asset` | `Path(…)` or an Unreal object path | — | **yes** |
| **`Parameter`** | `ParameterName` | a quoted string or a word | — | **yes** |
| `Group` | — | a quoted string or a word, where the engine's class has it | none | no |
| `SortPriority` | — | whole number, where the engine's class has it | node default | no |
| `Desc` | — | a quoted string or a word | none | no |

The collection is loaded and the parameter looked up when the node is built: a collection that does
not resolve or load is `DSH8213`, a name that is neither a scalar nor a vector parameter of it is
`DSH8254`. A call without `Collection` or `Parameter` is not checked <Since v="2.0.0" />. `Description`
is not an argument of this call — the node's description property is `Desc` — and is `DSH5213`.

The engine does not type the node's output, so the value is as wide as the place it is read into
<Since v="2.0.0" /> (1.x read the width off the loaded collection: `float4` for a vector parameter,
`float1` for a scalar). The declaration form declares it `float4` unless it says otherwise.

<Callout type="warn">
`Group` and `SortPriority` are taken only where the running engine's class has them. On an engine
whose class lacks them, `Group` is `DSH5213`, and `SortPriority` — a number — is kept with `DSH5291` and
fails with `DSH8212` when the node is built <Since v="2.0.0" /> (1.x dropped both silently below its
version gate).
</Callout>

`Path(…)` grammar and its accepted roots: [Asset References](/en/docs/parameters/path).

### UE.SceneTexture

Pure sugar.

```c
float4 scene = UE.SceneTexture(Id = "PostProcessInput0");
```

| Argument | Kind | Default | Required |
| :-- | :-- | :-- | :-- |
| **`Id`** | enum value | — | **yes** |

The front end rewrites the call to

```c
UE.Expression(Class = "SceneTexture", SceneTextureId = <Id>)[0]
```

— output 0 of `UMaterialExpressionSceneTexture`, *Color*, a `float4`. The call must have **exactly one**
argument and it must be named `Id`; anything else, an output selector included, is `DSH5255`. The
node's other properties and its `Size` / `InvSize` outputs need `UE.Expression(Class = "SceneTexture", …)`.

The `Id` is a value of `ESceneTextureId`, written without its prefix — `"PostProcessInput0"`. In a 1.x
source the prefixed name (`"PPI_PostProcessInput0"`), the `ESceneTextureId::` scope and another case
are accepted with `DSH5278`; a display name, or a spelling with spaces in it (`"ppi postprocessinput0"`),
is `DSH5215` <Since v="2.0.0" />. See [Enum values](/en/docs/builtins/ue-expression#enum-values).

## Properties declaration form

`UE.<Name>(…)` may also stand where a type token would in a
[`Properties`](/en/docs/language/sections#properties) section. It declares no parameter: the legacy front
end keeps the text and, in every `Graph` body that reads the property, declares a local of that name
at the head of the body, initialised with the call — `float2 UV = UE.TexCoord(Index = 0);` — one per such
body, in property order. A body that does not read the property gets no node. From there the call is an
ordinary `UE.` call, bound against the catalog <Since v="2.0.0" />.

```c
Properties {
    UE.TexCoord(Index = 0) UV;
    UE.CollectionParam(Collection = Path(Game, "MPC_Weather"), Parameter = "Wind") Wind;
}

Graph {
    Color = vec3(UV.x, UV.y, Wind);
}
```

| Rule | Declaration form | Expression form |
| :-- | :-- | :-- |
| `UE` | any case | exact |
| Argument syntax | `Key = Value` pairs split at top-level commas; a value is a quoted string, a number, `true` / `false`, a bare word (read as a name: another variable, or an enum value), or else kept as text, as `Path(…)` is | full expressions, including nested calls |
| The 1.x argument filter (`DSH5254`) | not applied | applied to the 27 names |
| Unknown argument | `DSH5213`; a number is kept with `DSH5291` and fails with `DSH8212` when the node is built | dropped with `DSH5254` on the 27 names |
| Duplicate argument, or both spellings of one (`Index` and `CoordinateIndex`) | `DSH4215` | same |
| A piece without `=`, an empty key or an empty value | skipped without a diagnostic | — |
| Inline default (`= …`) | `DSH3259` | not applicable |
| Metadata `[ … ]` | read and not applied | not applicable |
| Renamed arguments | `Description` → `Desc`; on `CollectionParam` / `CollectionParameter` `Asset` → `Collection` and `Parameter` → `ParameterName`, and the call is `UE.CollectionParameter` | none |
| `OutputType` / `ResultType` | the type of the local, not passed on — see [Declared output width](#declared-output-width) | see [OutputType](/en/docs/builtins/ue-expression#outputtype) |

The inline default is the one that bites. Put arguments inside the parentheses:

```c
// correct
UE.TexCoord(Index = 0) UV;

// wrong: DSH3259
UE.TexCoord UV = 0;
```

### Recognised names

| `UE.Name` | Node class | Arguments | Difference from the expression form |
| :-- | :-- | :-- | :-- |
| `TexCoord` | `TextureCoordinate` | `Index` or `CoordinateIndex`, `UTiling`, `VTiling`, `UnMirrorU`, `UnMirrorV` | `CoordinateIndex` is taken; a negative index is not checked <Since v="2.0.0" /> |
| `Time` | `Time` | `Period`, `IgnorePause` | `Period` is not range-checked, and it does **not** turn on the period override — write `bOverride_Period = true` <Since v="2.0.0" /> |
| `Panner` | `Panner` | `Coordinate`, `Time`, `Speed` (pins: a word is another variable, a number a constant on the pin), `ConstCoordinate`, `SpeedX`, `SpeedY`, `FractionalPart` | `ConstCoordinate` is taken |
| `WorldPosition` | `WorldPosition` | `ShaderOffsets` — the property `WorldPositionShaderOffset` | `ShaderOffsets` is taken |
| `ObjectPositionWS` | `ObjectPositionWS` | `Origin` — the property `OriginType` | `Origin` is taken |
| `CameraVectorWS`, `ScreenPosition`, `VertexColor` | as named | none of their own | an argument is an unknown argument |
| `CollectionParam`, `CollectionParameter` | `CollectionParameter` | `Collection` / `Asset`, `Parameter` / `ParameterName`, and `Group`, `SortPriority`, `Description` where the class has them | |
| *any other name* | the class of that name | its pins and properties | needs no `OutputType` <Since v="2.0.0" /> |

`ShaderOffsets` takes the values of `EWorldPositionIncludedOffsets` without their prefix — `Default`,
`ExcludeAllShaderOffsets`, `CameraRelative`, `CameraRelativeNoOffsets` — and, in another case or with the
`WPT_` prefix, with `DSH5278`. `Origin` takes `Absolute` and `CameraRelative`. The 1.x spellings that are
no value of the enum (`IncludingShaderOffsets`, `Absolute` and `NoOffsets` for `ShaderOffsets`, `World`
for `Origin`, …) are `DSH5215` <Since v="2.0.0" />.

### Declared output width

The type of the local comes from the first of these that applies:

1. an `OutputType` or `ResultType` argument naming a type — see
   [OutputType](/en/docs/builtins/ue-expression#outputtype);
2. the name, compared ignoring case: `TexCoord`, `Panner` → `float2`; `Time` → `float`;
   `WorldPosition`, `CameraVectorWS`, `ObjectPositionWS`, `VertexNormalWS`, `VertexTangentWS` → `float3`;
3. every other name → `float4`: `ScreenPosition`, `VertexColor`, `CollectionParam` /
   `CollectionParameter`, and any name outside the list <Since v="2.0.0" /> (1.x rejected such a name
   without an `OutputType`).

The call initialises the local like any initializer: a scalar output is spread across the local's
width, a wider one is cut down (`DSH5289`), and a narrower vector — a `float3` node under a name outside
the list — is `DSH4228`. An output the engine does not type, such as a collection parameter's, takes the
local's width. Give such a declaration an `OutputType`; a scalar collection parameter is
`OutputType = float1`.

A `const` in front of a `UE.*` declaration is read and ignored <Since v="2.0.0" /> (1.x rejected it).

## Details worth knowing

- A `UE.*` call may be swizzled directly — `UE.TexCoord(Index = 0).x` is an ordinary postfix chain. On a
  node of channel outputs, a swizzle that one output publishes is that output (`UE.VertexColor().a`). See
  [Operators and conversions](/en/docs/graph/expressions#swizzles).
- A property, local or parameter named `TexCoord` does not shadow `UE.TexCoord`; one named `UE` does —
  `UE.X(…)` is then a member call on that variable <Since v="2.0.0" />.
- On the 27 names, `OutputType`, `ResultType` and `Class` are dropped with `DSH5254` like any argument the
  name does not read. `Output`, `OutputName` and `OutputIndex` select an output of the node, as on every
  call <Since v="2.0.0" />.
- Inside a [`GraphFunction`](/en/docs/language/functions#graphfunction-and-ue-hoisting), `UE.*` calls are
  lifted out of the HLSL body and become generated input pins on the emitted Custom node.
- The plugin ships an HLSL header, `/Plugin/DreamShader/DreamShaderBuiltins.ush`, whose `DS_*` macros and
  functions mirror most of the nodes on this page (`DS_TIME`, `DS_WorldPosition(Parameters)`, …). Nothing
  in the plugin includes it; it is only useful inside a hand-written [`Function`](/en/docs/language/functions)
  HLSL body, with the `#include` first in the body. `DS_TexCoord` and `DS_VertexColor` depend on
  translator side effects nothing arranges any more — use `UE.TexCoord` and `UE.VertexColor` instead.

## Example

```c
Shader(Name="Docs/M_UEBuiltins")
{
    Properties {
        vec3 Tint = vec3(1.0, 0.6, 0.2);
        UE.TexCoord(Index = 0) UV0;
    }

    Settings {
        Domain       = "UI";
        ShadingModel = "Unlit";
    }

    Outputs {
        vec3 Color;
        Base.EmissiveColor = Color;
    }

    Graph {
        float2 uv   = UE.Panner(Coordinate = UV0, Time = UE.Time(), SpeedX = 0.1, SpeedY = 0.0);
        float3 wp   = UE.TranslatedWorldPosition();
        float3 nrm  = UE.TransformVector(UE.VertexNormalWS(), Source = "World", Destination = "Tangent");
        float  fade = UE.PerInstanceFadeAmount();
        float4 vcol = UE.VertexColor();

        Color = (vec3(uv.x, uv.y, wp.z) + nrm) * Tint * vcol.rgb * fade;
    }
}
```

Generated nodes:

```text
TextureCoordinate  (CoordinateIndex 0)        <- UV0        (a local at the head of Graph)
Panner             (Coordinate, Time, SpeedX) <- uv
Time                                          <- Panner.Time
WorldPosition      (camera-relative)          <- wp
VertexNormalWS                                -> Transform
Transform          (World -> Tangent)         <- nrm
PerInstanceFadeAmount                         <- fade
VertexColor                                   <- vcol
```
