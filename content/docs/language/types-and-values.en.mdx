description: The 52 type tokens, the per-context validity matrix, GLSL aliases, literals, and the tokens that no longer exist.

A type token is the first element of every declaration form in the language. The set is closed —
there are 52 tokens and no user-defined types — and it is matched **case-insensitively** in every
context.

Every type token goes through one table <Since v="2.0.0" />: a 1.x spelling is read as its 2.0 type
(`vec3` and `Float3` as `float3`, `MaterialAttributes` as `material`, `StaticBool` as `bool`) with no
diagnostic, and a word that is no type is kept as written for the binder to refuse (`DSH4201`) — in
`Properties` the front end refuses it first (`DSH3252`). The 2.0 type names are on
[DreamShaderLang 2.0](/en/docs/language-v2).

<Synopsis>

```c
// Properties section
[const] <type> <name> [ = <default> ] [ [ <metadata> ] ] ;

// Inputs / Outputs / Results of a material function
[opt] <type> <name> [ = <default> ] [ [ <metadata> ] ] ;

// Shader Outputs variable declaration
<type> <name> [ = <expression> ] ;

// Function / GraphFunction signature
Function [ <type> ] <name> ( [ { in | out } ] <type> <name> , … ) { … }

// Graph declaration
<type> <name> [ = { <expression> | { <brace-initializer> } } ] ;
```

</Synopsis>

<Grammar />

## Token families

| Family | Tokens | Count |
| :-- | :-- | --: |
| Scalar (1 component) | `float` `half` `double` `int` `uint` `bool`, and each with a `1` suffix (`float1` …) | 12 |
| Vector (2 / 3 / 4 components) | `float2..4` `half2..4` `double2..4` `int2..4` `uint2..4` `bool2..4` `vec2..4` `ivec2..4` `uvec2..4` `bvec2..4` | 30 |
| Texture | `Texture2D` `TextureCube` `Texture2DArray` `Texture3D` `VolumeTexture` | 5 |
| Opaque / other | `SamplerState` `MaterialAttributes` `Substrate` `StaticBool` `StaticBoolParameter` | 5 |

<Callout type="info">

There is no `vec1`, `ivec1`, `uvec1` or `bvec1`, and no `half` GLSL vector spelling. The
single-component GLSL-style forms do not exist; use `float` or `float1`. A token's width is its digit
suffix: `…2` to `…4` is a vector of that many components, `…1` or no digit a scalar, `…NxM` a matrix.

</Callout>

## The six contexts

The declaration positions do **not** share one type set. Each column of the matrix below is one
position.

| Column | Position |
| :-- | :-- |
| `Prop` | `Properties` of `Shader` / `ShaderFunction` / `ShaderLayer` / `ShaderLayerBlend` |
| `I/O` | `Inputs` / `Outputs` / `Results` of a material function or `VirtualFunction` (and `Properties` inside a `VirtualFunction`, where it aliases `Inputs`) |
| `Fn in` | an `in` parameter of `Function` / `GraphFunction` |
| `Fn out` | an `out` parameter, or the declared return type, of `Function` / `GraphFunction` |
| `Out decl` | a variable declaration inside a `Shader`'s `Outputs` section |
| `Graph` | a declaration statement inside a `Graph` block |

<Callout type="info">

`Prop` is checked by the front end while the section is read. The other columns are checked by the
binder for the whole file, and by the lowering to the graph where a value of the type would become a
pin — a type no pin carries is refused there, at the declaration or call that needs the pin
<Since v="2.0.0" />. 1.x checked a `Function`'s parameter types only when it was called; a token that
is no type is now `DSH4201` at the declaration.

</Callout>

## Validity matrix

`✔` accepted · `✘` rejected, with the code a rejection raises.

<Wide>

| Tokens | `Prop` | `I/O` | `Fn in` | `Fn out` | `Out decl` | `Graph` |
| :-- | :-: | :-: | :-: | :-: | :-: | :-: |
| scalars and vectors: the `float`, `half`, `int`, `uint`, `bool` families and their GLSL spellings | ✔ | ✔ | ✔ | ✔ | ✔ | ✔ |
| `Texture2D` `TextureCube` `Texture2DArray` `Texture3D` `VolumeTexture` | ✔ | ✔ ⁽¹⁾ | ✔ ⁽²⁾ | ✘ `DSH6254` | ✔ ⁽³⁾ | ✔ ⁽⁴⁾ |
| `MaterialAttributes` | ✘ `DSH3252` | ✔ | ✘ `DSH6210` | ✔ | ✔ | ✔ |
| `Substrate` | ✘ `DSH3252` | ✔ ⁽⁵⁾ | ✘ `DSH6253` | ✘ `DSH6253` | ✔ ⁽³⁾ | ✔ ⁽⁴⁾ |
| `StaticBool` | ✔ ⁽⁶⁾ | ✔ ⁽⁷⁾ | ✔ ⁽⁸⁾ | ✔ ⁽⁸⁾ | ✔ ⁽⁸⁾ | ✔ ⁽⁸⁾ |
| `StaticBoolParameter` | ✔ ⁽⁹⁾ | ✔ ⁽⁷⁾ | ✔ ⁽⁸⁾ | ✔ ⁽⁸⁾ | ✔ ⁽⁸⁾ | ✔ ⁽⁸⁾ |
| `mat2` `mat3` `mat4`, `float2x2` … `float4x4` | ✘ `DSH3252` | ✘ | ✘ | ✘ | ✘ | ✘ — see [Matrices](#matrices) |

</Wide>

1. A `Texture3D` input is a `VolumeTexture` pin.
2. A texture-typed `in` parameter of a `Function` also takes a companion `SamplerState <Name>Sampler`
   in the generated HLSL — the one the engine declares beside every texture input of a `Custom` node.
   See [Functions](/en/docs/language/functions).
3. A variable only: no `Base.` pin takes a texture, and a `Substrate` one goes only to
   `Base.FrontMaterial`. It has no zero value, so the `Graph` has to assign it before it is read.
4. Texture, `SamplerState` and `Substrate` declarations in a `Graph` block **must** carry an
   initializer — there is no default value for them: `DSH2215`.
5. A `Substrate` input is a Substrate pin of the function; Substrate values come from `Substrate.*`
   nodes, which the engine has from <Since v="5.4" ue /> on.
6. Read as `bool` <Since v="2.0.0" />, so `StaticBool X = true;` in `Properties` declares a **dynamic**
   bool parameter, not a static one; 1.x refused the token there. Write `StaticBoolParameter` for a
   static switch parameter.
7. An input of either token is a `StaticBool` pin of the function.
8. Read as `bool`.
9. In `Properties`, `StaticBoolParameter` is a **parameter-node token**, not a type token: it generates
   a `UMaterialExpressionStaticBoolParameter` and accepts only `true` / `false` as its default
   (`DSH3254` otherwise). See [Properties Types](/en/docs/parameters/properties).

<Callout type="warn">

`SamplerState` is a type of its own now <Since v="2.0.0" />; 1.x read it as `Texture2D` wherever it
accepted it. It is refused in `Properties` (`DSH3252`), as a material-function input (`DSH4364` — a
texture input carries its own sampler) and as a `Function` result (`DSH6254`), and a `Graph`
declaration of one needs an initializer (`DSH2215`).

</Callout>

## GLSL aliases

`vec` / `ivec` / `uvec` / `bvec` spellings are first-class tokens everywhere the corresponding
`float` / `int` / `uint` / `bool` spelling is accepted — in `Properties`, `Inputs`, `Outputs`, `Graph`
declarations and `Graph` constructors — and are read as that spelling.

| GLSL spelling | Equivalent |
| :-- | :-- |
| `vec2` `vec3` `vec4` | `float2` `float3` `float4` |
| `ivec2` `ivec3` `ivec4` | `int2` `int3` `int4` |
| `uvec2` `uvec3` `uvec4` | `uint2` `uint3` `uint4` |
| `bvec2` `bvec3` `bvec4` | `bool2` `bool3` `bool4` |

Every value in the graph is a float, so choosing between `int3`, `ivec3`, `bool3` and `float3` is
mostly documentation. The observable difference is division: a material graph has no integer
division, so a `/` whose operands are both integer constructor calls (`int(7) / int(2)`) is
`DSH4243`; every other `/` in a 1.x `Graph` is float division, and `7 / 2` is `3.5`
<Since v="2.1.1" /> (2.0.0 – 2.1.0 refused any division of two integers). See
[Operators and Conversions](/en/docs/graph/expressions).

### Rewrites inside `Function` bodies

A `Function` / `GraphFunction` **signature** reads every type token through the table above, and the
**body** runs every identifier through a superset of the same map. Both match on the lower-cased whole
identifier.

| Rewritten identifier | Becomes | In signature types | In body text |
| :-- | :-- | :-: | :-: |
| `vec2` `vec3` `vec4` | `float2` `float3` `float4` | ✔ | ✔ |
| `ivec2` `ivec3` `ivec4` | `int2` `int3` `int4` | ✔ | ✔ |
| `uvec2` `uvec3` `uvec4` | `uint2` `uint3` `uint4` | ✔ | ✔ |
| `bvec2` `bvec3` `bvec4` | `bool2` `bool3` `bool4` | ✔ | ✔ |
| `mat2` | `float2x2` | ✔ | ✔ |
| `mat3` | `float3x3` | ✔ | ✔ |
| `mat4` | `float4x4` | ✔ | ✔ |
| `mix` | `lerp` | ✘ | ✔ |
| `fract` | `frac` | ✘ | ✔ |
| `mod` | `fmod` | ✘ | ✔ |

15 signature aliases; 18 body aliases. The rewrite is comment- and string-aware and applies to
`Function` and `GraphFunction` bodies **only** — a `Graph` block, a `Shader` body and a
`ShaderFunction` body are not rewritten. In a `Graph` block `mix`, `fract` and `mod` call `lerp`,
`frac` and `fmod`, with the warning `DSH5277` <Since v="2.0.0" />; see
[Math Builtins](/en/docs/builtins/math).

<Callout type="warn">

The body rewrite matches the whole identifier, ignoring case. A helper, local variable or struct
member named `Mix`, `Mod`, `Fract`, `Vec3`, `Mat4` … inside a `Function` or `GraphFunction` body is
silently renamed to `lerp`, `fmod`, `frac`, `float3`, `float4x4`. There is no diagnostic (`DSH5277`
covers `Graph` text only); the failure surfaces as an HLSL compile error, or as silently different
math. Rename the identifier.

</Callout>

## Matrices

**There are no matrix values in a graph.** `mat2` / `mat3` / `mat4` and `float2x2` / `float3x3` /
`float4x4` are refused in `Properties` (`DSH3252`), and anywhere else a value of a matrix type that
would become a node or a pin is `DSH4361`.

`mat2` / `mat3` / `mat4` are nevertheless accepted *lexically* in a `Function` signature, which reads
them as `float2x2` … `float4x4`. The declaration therefore parses, and the call fails:

```c
Function float3 Rotate(in mat3 basis, in vec3 v) { return mul(basis, v); }
// parses; a Graph call that passes a matrix to 'basis' is DSH4361
```

Matrix-shaped work goes through the transform builtins (see [UE.* Nodes](/en/docs/builtins/ue-nodes)),
or entirely inside an HLSL body.

## Literals

### Scalars

```c
float a = 1.0;
float b = -0.5;
float c = 1e-3;
```

A number is a real token everywhere, with an optional exponent and a type suffix (`f F h H` a float,
`u U l L` an integer) that is part of the token text: `0.55f` is `0.55`. A declaration default reads
that token the way its consumer asks; `float Strength = 1abc;` is now `DSH2105` plus `DSH3254`, no
longer a silent `1.0` <Since v="2.0.0" />. See
[Lexical Elements](/en/docs/language/lexical#numeric-literals).

### Vector construction

```c
vec2   uv    = vec2(0.5, 0.5);
vec3   color = vec3(1.0, 0.2, 0.1);
float4 rgba  = float4(color, 1.0);
```

A constructor's component count is its name's digit suffix. It accepts any mix of scalars and vectors
whose parts add up to the target width.

### Brace initializers

```c
vec3   color = {1.0, 0.2, 0.1};
float4 rgba  = {color, 1.0};
```

A brace list as a declaration's initializer is rewritten to a constructor call of the declared type —
handy for assembling a target type from existing scalars or vectors.

### Booleans and strings

`true` and `false` are accepted in declaration defaults, converting to `1.0` / `0.0` where a scalar is
expected. String literals appear in settings values, metadata, class names and named `UE.*`
arguments; they are **not** values an expression can compute with.

```c
Settings = { Domain = "UI"; }

float pulse = UE.Expression(Class="Sine", OutputType="float1", Input=UE.Time());
```

## Asset references

Texture and asset-typed declarations take a `Path( … )` reference rather than a literal:

```c
Properties = {
    Texture2D   MainTex     = Path(Game, "Textures/T_Main");
    Texture2D   PluginTex   = Path(Plugins.MoonToon, "Textures/T_Plugin");
    Texture2D   DefaultTex  = Path("/Engine/EngineResources/DefaultTexture");
    TextureCube SkyTex      = Path(Engine, "EngineResources/DefaultTextureCube");
    Texture2D   Pasted      = Texture2D'/Game/Textures/T_X.T_X';   // Copy Reference, since 1.9.0
}
```

Every accepted spelling, both resolvers and all their diagnostics: [Path References](/en/docs/parameters/path).

## Whitespace inside a token

A type token is one word <Since v="2.0.0" />. 1.x removed the spaces inside a token in some contexts,
so `float 3` read as `float3` and `Material Attributes` as `MaterialAttributes` there; now they are two
words, and the declaration does not parse.

## Generated HLSL spelling

When a `Function` is lowered to HLSL, each declared type is written into the signature in its 2.0
spelling:

| Declared token | HLSL emitted |
| :-- | :-- |
| `VolumeTexture` | `Texture3D` |
| `MaterialAttributes` | `FMaterialAttributes` — as a result only; as an input it is `DSH6210` |
| `StaticBool`, `StaticBoolParameter` | `bool` <Since v="2.0.0" /> |
| a GLSL spelling or another case (`vec3`, `Float3`) | the 2.0 spelling (`float3`) |
| everything else | the token, as written |

1.x wrote `MaterialAttributes`, `StaticBool` and `StaticBoolParameter` verbatim, which produced a
helper Unreal could not compile; that no longer happens <Since v="2.0.0" />.

## Removed tokens

| Token | Status | Replacement |
| :-- | :-- | :-- |
| `Scalar` | **removed** | `float` |
| `Color` | **removed** | `float4` / `vec4` |
| `Vector` | **removed** | `float2` … `float4` / `vec2` … `vec4` |

They are not special-cased anywhere; they are refused like any word that is no type — `DSH3252` in
`Properties`, `DSH4201` everywhere else.

## Example

One token from each family, each in a context that accepts it:

```c
ShaderFunction(Name="Functions/F_Types")
{
    Properties = {
        float     Strength = 1.0;              // scalar token
        vec3      Tint     = vec3(1, 1, 1);    // GLSL vector spelling
        Texture2D Noise    = Path(Game, "Textures/T_Noise");
    }

    Inputs = {
        vec2                   UV;             // numeric
        opt StaticBool         UseTint;        // a StaticBool pin
        opt MaterialAttributes InAttrs;        // a MaterialAttributes pin
    }

    Outputs = {
        vec3 OutColor;
    }

    Graph = {
        Texture2D Src = Noise;                 // a texture declaration needs an initializer
        vec4   Sampled = SampleTexture2D(Src, UV);
        float3 Base    = Sampled.rgb * Strength;
        OutColor       = Base * Tint;
    }
}
```
