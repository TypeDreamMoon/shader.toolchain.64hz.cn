This page covers the character-level rules: which tokens care about case, how comments and literals
are read, how a section body is cut into statements, and the `#if` preprocessor that runs before all
of it.

One lexer reads every source — `.dss` and 1.x alike — into one token stream, and the legacy front end
reads the 1.x grammar from those tokens <Since v="2.0.0" />. Through 1.9.x the declaration grammar and
the `Graph` grammar each had a character scanner of its own, with rules of their own. Three options
apply to a `.dsm` / `.dsf`: a `///` line is an ordinary comment, a `'…'` pair on one line is a string
(the Content Browser's `Texture2D'…'` shell), and a `#` line at the start of a line is a directive
token.

## Case sensitivity

**Top-level block keywords and the lower-case reserved words are case-sensitive.** Everything else
keyword-like in the 1.x grammar is matched ignoring case, with the exceptions marked below. Names the
engine defines — material attributes, node classes, pins — are matched exactly; in a 1.x file one
that matches only ignoring case still resolves, with the warning `DSH5276`, and so does a name the
file declares, with `DSH5275` <Since v="2.0.0" />. The [preprocessor](#preprocessor), which runs
before the grammar, is case-sensitive throughout.

| Construct | Case-sensitive |
| :-- | :-- |
| Top-level block keywords — `Shader`, `ShaderFunction`, `ShaderLayer`, `ShaderLayerBlend`, `MaterialLayer`, `MaterialLayerBlend`, `VirtualFunction`, `Namespace`, `Function`, `GraphFunction` | **yes** |
| Reserved words — `in`, `out`, `const`, `return`, `true`, `import`, … | **yes**, as reserved words; `In`, `Const`, `True` are ordinary words that the 1.x grammar still reads where it expects the keyword |
| Section names — `Properties`, `Settings`, `Outputs`, `Inputs`, `Results`, `Options`, `Graph`, `Code`, `Layout` | no |
| Header attribute keys — `Name=`, `Root=`, `Asset=` | no |
| `Settings` / `Options` keys, metadata keys, `Expression( … )` argument keys, `Layout` argument keys | no |
| `UE.*` argument names, `Base.` attribute names | no, with `DSH5276` |
| Type tokens — `float3`, `vec3`, `Texture2D`, `ScalarParameter`, … | no |
| `const` prefix in `Properties`, `opt` prefix in `Inputs` | no |
| `SelfContained` / `Inline` after `Function` | no |
| `in` / `out` parameter qualifiers | no |
| `true` / `false` | no |
| `Path(` asset-reference keyword | no |
| `Base.` binding prefix, `Expression(`, `.Pin[` | no |
| `Group("…")` property-scope head, `Slider(` metadata shorthand | no |
| `UE.` builtin prefix | no in `Properties` and in a `GraphFunction` body; **yes** in a `Graph` call <Since v="2.0.0" /> |
| `#Region` / `#EndRegion` | no |
| `Node(` / `Comment(` layout calls | no |
| `import` | no, with the warning `DSH2253` for another case |
| `#if` / `#ifdef` / `#ifndef` / `#elif` / `#else` / `#endif` / `#define` / `#undef` | **yes — lowercase only**; `#IF` is `DSH1035`, not a silent no-op |
| define **names**, and the reserved `DS_` prefix test | **yes** — `Foo` and `FOO` are two defines, and `ds_foo` is not reserved |
| string comparison inside a `#if` | **yes** — `DS_PLATFORM == "windows"` is false on Windows |
| `default` call-argument sentinel | **yes** — lower case only <Since v="2.0.0" /> |
| `.dsm` / `.dsf` / `.dsh` extensions | no |

So `shader(Name="X")` and `SHADER(Name="X")` are both syntax errors (`DSH2240`), while
`properties = { … }`, `settings { domain = "ui"; }` and `Shader(name="X")` are all accepted.

A keyword is a whole word: `ShaderFunction` is its own identifier, never `Shader` followed by
something, and `ShaderLayerBlend` is never `ShaderLayer`.

## Synopsis

<Synopsis>

```c
<token> := <identifier> | <keyword> | <string-literal> | <number> | <punctuation>

<identifier>     := { <letter> | _ } { <letter> | <digit> | _ }…
<qualified-name> := <identifier> :: <identifier>
<string-literal> := " { <character> | \<escape> }… "
<punctuation>    := { | } | ( | ) | [ | ] | ; | = | , | . | : | # | the operators of a Graph expression
```

</Synopsis>

<Grammar />

Whitespace and comments may appear between any two tokens and are otherwise insignificant.

## Whitespace

Space, tab, vertical tab, form feed, carriage return and line feed separate tokens. Only ASCII
whitespace counts <Since v="2.0.0" />: other Unicode whitespace — a no-break space a browser copy left
behind — is `DSH2101`. Newlines carry no syntactic weight; they matter only to
[preprocessor](#preprocessor) directives, `#Region` directives inside a `Graph` body (see
[Layout and #Region](/en/docs/language/layout)), and diagnostic line numbers.

Any whitespace separates any two words, in every section <Since v="2.0.0" />: a tab between a type
and a name is as good as a space.

## Comments

| Form | Rule |
| :-- | :-- |
| `// …` | line comment; runs to, but does not include, the next line break. `///` is an ordinary line comment in a 1.x file |
| `/* … */` | block comment; ends at the first `*/` |

- **Block comments do not nest.** `/* a /* b */ c */` ends at the first `*/`; the trailing `c */` is
  code again.
- **An unterminated block comment is an error** <Since v="2.0.0" />: `DSH2102`, reported at the
  opening `/*`. 1.x accepted it and dropped the rest of the file.
- Comments are recognized identically everywhere, inside `Graph` bodies too and while braces,
  parentheses and brackets are counted, so a brace or quote inside a comment never unbalances a
  block.

<Callout type="warn">

**A comment hides an `import`; it does not hide a preprocessor directive.** `import` is a token
<Since v="2.0.0" />, so one inside `/* … */` is commented out. The `#if` family is found by a line scan
that runs before any comment is understood, so a `#if` inside `/* … */` is still a directive; only a
line whose first non-whitespace characters are `//` is guaranteed not to be. Comment directives out
with `//` per line.

</Callout>

## Identifiers

| Position | Accepted characters |
| :-- | :-- |
| first | an ASCII letter or `_` |
| subsequent | an ASCII letter, a digit or `_` |

- There is no length limit. Only ASCII letters count <Since v="2.0.0" />; another letter is
  `DSH2101`.
- **Block words, section names and type names are not reserved.** A property, variable, parameter or
  function may be named `Shader`, `Graph` or `float`; whether it then resolves is a matter for the
  context it appears in. The lower-case reserved words below are reserved.
- A declaration name is one identifier token in every section <Since v="2.0.0" />. 1.x checked only
  that a `Properties` name was non-empty, so `Properties { float 1Bad = 0; }` parsed; now `1Bad` is a
  malformed number (`DSH2105`) and the declaration is `DSH3250`.
- Namespace-qualified names use `::`, as in `Common::ApplyTint`. See
  [Functions](/en/docs/language/functions#namespace).

### Reserved words

One lexer reads every file, and its keywords are reserved in a 1.x file too, in lower case
<Since v="2.0.0" />:

`uniform` `static` `const` `extern` `export` `in` `out` `inout` `struct` `if` `else` `for` `while` `do`
`return` `break` `continue` `discard` `true` `false` `import`

None of them can name a property, an output, an input or a `Graph` variable. Another case is an
ordinary word: `Const` and `IN` are read as `const` and `in` where the 1.x grammar expects those, and
`True` as `true`. Besides these, a `Function` / `GraphFunction` parameter may not be called
`__return` (in any case, `DSH6303`), and a preprocessor define name may not begin with `DS_`
(`DSH1039`).

### Name sanitization

When a name reaches generated HLSL it is sanitized: every character outside `A–Z a–z 0–9 _` becomes
`_`, a leading digit gains a `_` prefix, runs of consecutive `__` collapse to one, and a result that is
empty or entirely underscores becomes `DreamShaderSymbol`.

```text
Common::ApplyTint   →   Common__ApplyTint   →   Common_ApplyTint
```

That collapse is why `Common::ApplyTint` and a top-level `Common_ApplyTint` are the same name
(`DSH4210`).

## String literals

A string is opened by `"`, ends at the next unescaped `"` **on the same line**, and is unescaped by
the lexer.

| Escape | Produces |
| :-- | :-- |
| `\n` | line feed |
| `\r` | carriage return |
| `\t` | tab |
| `\"` | `"` |
| `\\` | `\` |
| `\0` | nothing — a string cannot hold a NUL |
| `\<any other character>` | `DSH2104` <Since v="2.0.0" /> (1.x dropped the backslash and kept the character) |

- A string never spans lines <Since v="2.0.0" />: a line break before the closing `"` ends it, and an
  unclosed string is `DSH2103`, in a section and in a `Graph` body alike. 1.x let a string run across
  lines, and closed one in a `Graph` body silently at the end of the input.
- In a 1.x file and a `.dsh`, a pair of `'` on one line is a string too, with no escapes — the shell of
  a Content Browser reference, `Texture2D'/Game/T.T'`. A lone `'` is `DSH2101`.
- Write Windows paths with forward slashes: `"D:\new\textures"` holds the escapes `\n` and `\t`.

Anywhere a value may be quoted — settings values, metadata values, attribute values, argument values —
quoting is **optional**: `Domain = UI;` and `Domain = "UI";` are equivalent. A quoted value is the
string's text; an unquoted one is the text of its tokens.

<Callout type="info">

A quoted `Settings` or `Options` value is not trimmed: `Domain = " UI ";` stores `UI` with its spaces.

</Callout>

## Numeric literals

### Declaration grammar

A number is a token everywhere <Since v="2.0.0" />, lexed by the
[Graph expression rules](#graph-expression-grammar) below; a section then reads the token's text the
way its consumer asks:

| Consumer | Accepts |
| :-- | :-- |
| scalar default | an optional sign, digits, at most one `.`, an optional exponent, an optional trailing `f` / `F`; or `true` / `false` |
| integer argument (`SortPriority`, `Layout` coordinates) | an optional sign and digits |
| boolean default | exactly `true` or `false`, in any case |
| vector default | `<anything>( <part> [, <part>]… )` — see below |

What is not accepted is `DSH3254` for a default, `DSH3258` for a `SortPriority` and `DSH3275` for a
`Layout` coordinate.

| Written | Read as | Diagnostic |
| :-- | :-- | :-- |
| `float Strength = 1.0f;` | `1.0` | none |
| `float Strength = 0.0f;` | `0.0` | none |
| `float Strength = 1abc;` | — | `DSH2105` and `DSH3254` <Since v="2.0.0" /> (1.x silently read `1.0`) |
| `float Strength = abc;` | — | `DSH3254` |
| `float Strength = 0x1F;` | — | `DSH3254` |
| `float Strength = 1e3;` | `1000.0` | none <Since v="2.1.1" /> (2.0.0 – 2.1.0: `DSH3254`) |

The vector-literal form is deliberately loose, as in 1.x. The first `(` and the **last** `)` delimit
the components, and **the text before `(` is ignored entirely** — `float3(1,0,0)`, `vec3(1,0,0)`,
`(1,0,0)` and `Nonsense(1,0,0)` all read identically. The interior is split on `,` without tracking
nesting, so a nested call in a component breaks the split. Each component may be a number (with an
exponent and a trailing `f`) or `true` / `false`.

| Component count | Result |
| :-- | :-- |
| 1 | `(a, a, a, 1)` — splat to x, y, z |
| 2 | `(a, b, 0, 0)` |
| 3 | `(a, b, c, 1)` |
| 4 or more | the first four; components past the fourth are ignored |

The unfilled default is `(0, 0, 0, 1)`.

### Graph expression grammar

| Element | Rule |
| :-- | :-- |
| start | a digit, **or** `.` immediately followed by a digit — so `.5` is legal |
| body | digits, then at most one `.` and more digits |
| exponent | `e` or `E`, optionally followed by `+` or `-`, then digits |
| suffix | `f` `F` `h` `H` make a float, `u` `U` `l` `L` an integer |
| hexadecimal | `0x1F` is one hexadecimal integer token; in a 1.x `Graph` expression it is `DSH2222` <Since v="2.0.0" /> (1.x read `0` followed by the name `x1F`, so the value was silently 0) |
| anything glued on | `1.2.3`, `1abc`, `1e`, `1.0u`, `1fu` are one malformed token: `DSH2105` |

The suffix is part of the token text, so `0.55f` is the number `0.55`.

Every operator of the 2.0 grammar is a token <Since v="2.0.0" />: `%`, `<`, `!`, `&&`, `?`, `[`, `]`
no longer end a `Graph` expression and drop the rest of it. What a 1.x `Graph` did not have is refused
by name instead — `DSH2200` to `DSH2222`. See [Unsupported Constructs](/en/docs/graph/unsupported).

## Statement separation

A section body is a list of `;`-separated statements, read token by token <Since v="2.0.0" />.

- A `;` separates statements only outside `()`, `[]` and `{}`. A string is one token, so a `;` inside
  one is just text.
- Empty statements are skipped, so stray `;;` is harmless.
- The `;` of the last statement before the section's closing `}` is optional.
- The `;` after a section's closing `}` is optional, and so is the `=` between a section name and its
  block <Since v="1.5.0" />.
- A value — a default, a setting, a binding source, an argument — runs to the `;`, `,` or `)` that
  ends it outside brackets, so an unquoted attribute value may hold parentheses and commas:
  `Asset = Path(Game, "MaterialFunctions/F_X")` is one value.

<Callout type="info">

1.x split statements with three different splitters, two of which looked for a literal space, so
`float3<TAB>Color;` failed in `Inputs`, `Outputs`, `Results` and a `Shader`'s `Outputs`, and
`opt<TAB>float X` did not mark an input optional. Both work now <Since v="2.0.0" />.

</Callout>

## Preprocessor

<Since v="1.9.0" />

`#if` / `#ifdef` / `#ifndef` / `#elif` / `#else` / `#endif`, plus `#define` and `#undef`:
line-oriented directives evaluated **before** the source is parsed. A branch that is not taken never
reaches the parser and never becomes a node. It belongs to neither grammar.

<Synopsis>

```c
#if      <expr>
#ifdef   <NAME>        // exactly #if  defined(NAME)
#ifndef  <NAME>        // exactly #if !defined(NAME)
[#elif   <expr>]…
[#else]
#endif

#define  <NAME> [<value>]
#undef   <NAME>
```

</Synopsis>

### What it is for

`#if` does the one thing a [static switch](/en/docs/parameters/properties) cannot: cut the
**declaration** layer. A static switch is a node inside `Graph` that chooses between two values; when
two builds of a material differ by a `ShadingModel` line, a different set of `Outputs`, a different
`import` or a whole `ShaderFunction` block that should not exist, only `#if` can say it.

| | `#if` | `StaticSwitchParameter` / `StaticBool` |
| :-- | :-- | :-- |
| Evaluated | at generation time, over source text | when the material's shader permutation is compiled |
| Can select between | any two spans of lines outside a `Function` body | two expressions inside a `Graph` body |
| Reaches `Settings`, `Outputs`, `Properties`, `import`, whole blocks | **yes** | no |
| Chosen by | the project's define table — one answer per compile | a material instance — one answer per instance |
| Untaken branch | nowhere; never validated | in the asset, as nodes |
| Changing the answer costs | a rebuild of every source that reads the define | ticking a checkbox on an instance |

Read it as one rule: **`#if` is a project-wide, build-time decision; a static switch is a
per-instance, artist-facing one.** The environment decides and the difference is a declaration
(Substrate on or off, an engine version, a platform-specific `Outputs`) → `#if`; whoever tweaks a
material instance should decide → a static switch.

### Recognition

Each physical line is tested; a line that fails a rule is passed to the parser unchanged.

| # | Rule |
| :-- | :-- |
| 1 | the line is outside every `Function` / `GraphFunction` body |
| 2 | the trimmed line does not start with `//` — so `// #if FOO` is a comment |
| 3 | the first non-whitespace character is `#`; whitespace may follow the `#` |
| 4 | the keyword is one of the eight, **lowercase only** |
| 5 | after the operand only whitespace and a `//` comment may follow, or it is `DSH1042`; `#define` is exempt, its value runs to the end of the line |
| 6 | `#if` blocks nest, to a depth of 64 |
| 7 | `#else` closes the chain — no `#elif` and no second `#else` may follow it |

Other `#` lines outside a `Function`: `#Region` / `#EndRegion` (any case) pass through to the parser;
`#pragma` and `#include` in a `.dss` or `.dsh` pass through to the 2.0 parser; everything else is
`DSH1035` — `#IF`, `#endfi` and similar typos included, and an `#include` at the declaration level of
a `.dsm` / `.dsf` (the spelling there is [`import`](/en/docs/language/imports)). A misspelt `#endfi` is
never swallowed silently, because everything below it would then be enabled unconditionally.

<Callout type="warn">

**`Function` and `GraphFunction` bodies are the shader compiler's.** A body is HLSL, and a `#if` there
addresses HLSL's own preprocessor and the engine's defines (`MATERIALBLENDING_SOLID`, `PIXELSHADER`, …).
DreamShader's preprocessor does not descend into bodies: their `#` lines pass through verbatim, are
not paired and do not count toward nesting. The other way round, **you cannot write a DreamShader
`#if` inside a body** — to choose between two bodies at generation time, put the `#if` around the
`Function` blocks:

```c
#if DS_SUBSTRATE
Function ApplyShading(in float3 C, out float3 R) { R = SubstratePath(C); }
#else
Function ApplyShading(in float3 C, out float3 R) { R = LegacyPath(C); }
#endif
```

A `Graph` body is DreamShaderLang, not HLSL, so a `#if` in a `Graph` is DreamShader's.

</Callout>

### Conditional expressions

`defined(NAME)` / `defined NAME`, `!`, `&&`, `||` (short-circuiting), `==` `!=` `<` `<=` `>` `>=`,
`+ - * / %` and parentheses. There are two kinds of value, a 64-bit signed **integer** and a
**string**; a condition is true when it evaluates to a non-zero integer.

| Expression | Evaluates to |
| :-- | :-- |
| an integer literal | itself; decimal, or `0x` hexadecimal |
| a `"…"` literal | that string |
| `defined(X)` | `1` when `X` is defined, `0` when it is not |
| an identifier that is **not defined** | the integer `0`, as in C |
| an identifier defined to an **empty** value | the integer `1` — so a bare `#define FOO` is a switch |
| an identifier whose whole value is an integer literal | that integer (`-3` counts) |
| any other defined identifier | its value, as a string |

- `==` / `!=` between two strings is literal and **case-sensitive**.
- Comparing a string with an integer, arithmetic or ordering on a string, and a string used as a truth
  value (`#if DS_PLATFORM`) are `DSH1040` — never a silent true or false. For a version gate use the
  integer `DS_ENGINE_MAJOR` / `DS_ENGINE_MINOR`, not the `DS_PLUGIN_VERSION` string.
- `/` and `%` truncate toward zero; by zero they are `DSH1041`.
- A `#define`'s value is the **text** after the name to the end of the line (a trailing `//` comment
  removed first), never expanded and never evaluated: `#define PP_SUM 1 + 1` is the string `"1 + 1"`,
  not `2`. There are no macros and no `#include`.

```c
#if DS_ENGINE_MAJOR > 5 || (DS_ENGINE_MAJOR == 5 && DS_ENGINE_MINOR >= 7)
```

### Where defines come from

Five tiers, resolved in order; a later tier overwrites an earlier one — **except `Builtin`, which
never loses**. Names are case-sensitive and must match `[A-Za-z_][A-Za-z0-9_]*`.

| # | Tier | Set from |
| --: | :-- | :-- |
| 1 | `Builtin` | the `DS_` constants below, read-only |
| 2 | `Settings` | *DreamPlugin ▸ Dream Shader ▸ Compiler ▸ Preprocessor Defines* in the project settings (written to `DefaultEngine.ini`, checked in) |
| 3 | `Registered` | `UE::DreamShader::RegisterDreamShaderDefine()` from C++ |
| 4 | `Provider` | `RegisterDreamShaderDefineProvider()` from C++, pulled fresh at resolve time |
| 5 | `CommandLine` | `-Define=NAME=VALUE` on the commandlet (`-D=` for short, repeatable; no value means empty) |

| Builtin | Type | Value |
| :-- | :-- | :-- |
| `DS_ENGINE_MAJOR` / `DS_ENGINE_MINOR` / `DS_ENGINE_PATCH` | integer | the engine version |
| `DS_SUBSTRATE` | integer | `1` with Substrate enabled, else `0` (from the read-only CVar `r.Substrate`) |
| `DS_PLATFORM` | string | the ini platform name, for example `"Windows"` — the same in the editor and in a cook |
| `DS_PLUGIN_VERSION` | string | the plugin version, `"unknown"` if unavailable; always defined |

The `DS_` **prefix** is reserved: a `#define` / `#undef` of such a name in a source is `DSH1039`; such
an entry in the project settings or `-Define=` is dropped with a warning, and
`RegisterDreamShaderDefine` returns `false`. The test is case-sensitive, so `ds_foo` is free to use.

### `#define` is file-local

A `#define` is visible **only in the file that writes it** — not in the file that imports it, and not
in a file imported after it. This is not C. Every file, an imported header included, is preprocessed
on its own against the compile's define table before it is parsed. Because preprocessing comes first,
a `#if` can wrap an `import`: when its branch is cut, the `import` is not read at all.

```c
#if DS_SUBSTRATE
import "Shared/SubstrateHelpers.dsh";
#else
import "Shared/LegacyHelpers.dsh";
#endif
```

To define a switch centrally, use a channel built for it: *Preprocessor Defines* in the project
settings, registration from C++, or `-Define=` for a one-off build.

### Consequences

- **An inactive branch is not checked at all.** It is never lexed, parsed or type-checked. A branch
  nobody builds rots silently: keep branches short, and run the commandlet with `-Force` once per
  define set you ship.
- **Line counts are preserved.** Every directive line and every cut line becomes an empty line, so a
  diagnostic still points at the line you wrote.
- **The dependency graph reads the raw file.** It evaluates no condition, so a file's dependencies are
  the **union over all branches**: editing a `.dsh` only a dead branch imports still rebuilds its
  dependents.
- **The build key records only the defines a source actually read** (an undefined one as `<undef>`),
  so changing a define rebuilds only the sources that read it. Changing the define table also rebuilds
  the editor's Ephemeral materials.
- **A source with directives cannot be adopted** (`DSH8149`): the asset holds only the branch that was
  taken, and rewriting the source from it would delete the others. Revert and Detach are unaffected.
  The VirtualFunction startup sync refuses such a file too (`DSH9001`). An HLSL `#if` inside a function
  body and `#Region` do not count as directives.
- **The decompiler never emits a directive** — conditional compilation is one-way syntax.
- **Cutting away a whole `Shader` block does not delete its asset**; the file simply stops building
  it. A `.dsm` left with no block at all is `DSH2254`.
- A preprocessor failure stops the compile before parsing and is reported as `DSH8291`, which carries
  the preprocessor's own `DSH103x` code and the position of the offending directive; the preprocessor
  stops at its first error.

```c
Shader(Name="Materials/M_Foo", Root="Game")
{
    Settings = {
        Domain = "Surface";
#if !DS_SUBSTRATE
        ShadingModel = "DefaultLit";
#endif
    }

    Properties { vec3 Tint = vec3(0.8, 0.2, 0.1); }

    Outputs = {
#if DS_SUBSTRATE
        Substrate Surface;
        Base.FrontMaterial = Surface;
#else
        vec3 BaseColor;
        Base.BaseColor = BaseColor;
#endif
    }

    Graph = {
#if DS_SUBSTRATE
        Surface = Substrate.Slab(DiffuseAlbedo = Tint, Roughness = 0.4);
#else
        BaseColor = Tint;
#endif
    }
}
```

## Example

```c
// Line comment before the top-level declaration.
Shader(Name="Materials/M_Comments")
{
    /* Block comment
       spanning multiple lines. */
    Settings = {
        Domain = "UI";        // trailing line comment
        ShadingModel = Unlit; // quotes are optional
    }

    Properties {
        // Any whitespace may separate a type from its name.
        ScalarParameter Rough = 0.5 [Group="Surface"; Slider(0, 1)];
        vec3            Tint  = vec3(1.0, 0.4, 0.1);
        float           Fudge = 1.0f;   // reads as 1.0
    }

    Outputs {
        vec3	Color;                  // a tab is whitespace too
        Base.EmissiveColor = Color
    }                                   // the last ';' in a block is optional

    Graph {
        vec2 UV = UE.TexCoord(Index = 0);
        Color = vec3(Rough, Rough, UV.x) * Tint;
    }
}
```

## Diagnostics

Every diagnostic carries the file, line and column of the construct it is about, and is printed
`<file>(<line>,<column>): DSHnnnn: <message>` <Since v="2.0.0" />; only a few that concern a whole
file, such as an import that cannot be resolved, report line 1. 1.x located only the messages that
ended in `near index {Index}`.

<Diag>
  <D msg="DSH2101: Unexpected character '{0}' in source." cause="A character that begins no token: outside ASCII, $, @, a backtick, full-width punctuation, a lone ', or an invisible no-break space." fix="Delete it; a character that looks ordinary is almost always the invisible kind, so retype the line." />
