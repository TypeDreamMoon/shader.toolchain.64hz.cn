The value-producing half of the Graph language: literals, identifiers, calls, member access and the
four arithmetic operators, lowered into `UMaterialExpression` nodes. Everything on this page also
applies to `Outputs` binding expressions and `Outputs` declaration defaults — they are single
expressions of the same grammar.

## Synopsis

<Synopsis>
```c
<expression>     := <additive>
<additive>       := <multiplicative> [ { + | - } <multiplicative> ] …
<multiplicative> := <unary> [ { * | / } <unary> ] …
<unary>          := { + | - } <unary> | <postfix>
<postfix>        := <primary> [ <postfix-op> ] …
<postfix-op>     := . <identifier> | :: <identifier> | ( [ <argument> [ , <argument> ] … ] )
<primary>        := <identifier> | <number-literal> | <string-literal> | ( <additive> )
<argument>       := [ <identifier> = ] <additive>
```
</Synopsis>

This is the 1.x grammar. The legacy front end parses an expression with the 2.0 grammar, which is a
superset, and refuses everything outside the grammar above with a code <Since v="2.0.0" /> — see
[Operators that do not exist](#operators-that-do-not-exist).

## Precedence and associativity

Highest binding first.

| Level | Operators | Arity | Associativity | Notes |
| :-- | :-- | :-- | :-- | :-- |
| 1 | `f(…)` call, `.member`, `::name` | postfix | left | Chains freely: `A::F(x).rgb.b` |
| 2 | `+` `-` | unary, prefix | right | Recursive: `- -x` is legal; `--x` without the space is the decrement operator, `DSH2207` |
| 3 | `*` `/` | binary | left | `a / b / c` is `(a / b) / c` |
| 4 | `+` `-` | binary | left | `a - b - c` is `(a - b) - c` |
| — | `( … )` grouping | — | — | Overrides the levels above; creates no node |

### Operators that do not exist

The 1.x expression grammar has no other operators. Each of the following parses, and is then refused:

| Category | Spellings | Code |
| :-- | :-- | :-- |
| Modulo | `%` — use the `fmod` builtin | `DSH2201` |
| Comparison | `==` `!=` `<` `>` `<=` `>=` — legal **only** in an `if` condition | `DSH2200` |
| Logical | `&&` `\|\|` `!` | `DSH2200` |
| Bitwise / shift | `&` `\|` `^` `~` `<<` `>>` | `DSH2201` |
| Conditional | `? :` | `DSH2200` |
| Increment / decrement | `++` `--` | `DSH2207` |
| Compound assignment | `+=` `-=` `*=` `/=` and the rest | `DSH2205` |
| Assignment inside an expression | `=`, outside a named call argument | `DSH2204` |
| Indexing | `[ ]` — use a [swizzle](#swizzles) | `DSH2202` |
| Cast | `(float3)x` — use a constructor | `DSH2203` |
| Comma operator | `,`, outside a call argument list | none of its own: the statement ends there, so what follows is usually `DSH2154` |
| Matrices | none exist | `DSH4361` for a matrix value |

<Callout type="warn">
**1.x truncated these silently.** Its tokenizer mapped every character it did not know (`%`, `!`, `<`,
`>`, `&`, `|`, `^`, `~`, `?`, `[`, …) to the end of the input, so the parser kept the expression before
it and dropped the rest without a message. Since <Since v="2.0.0" /> the whole expression is read and the
operator is refused:

| Written | 1.x built | Code now |
| :-- | :-- | :-- |
| `a % b` | `a` | `DSH2201` |
| `a && b` | `a` | `DSH2200` |
| `a ? b : c` | `a` | `DSH2200` |
| `v[0]` | `v` | `DSH2202` |
| `a << 2` | `a` | `DSH2201` |

A character that is no token at all (`@`, `$`, a backtick) is `DSH2101`. Parenthesising a suspect
expression is no longer needed to make a truncation visible. The full list is on
[What Graph Is Not](/en/docs/graph/unsupported).
</Callout>

## Operand rules

The binder applies these tests to both operands of `+ - * /`:

| # | Test | On failure |
| --: | :-- | :-- |
| 1 | Both operands are numbers or bools — not a texture, a sampler or a `MaterialAttributes` value | `DSH4226` |
| 2 | A `Substrate` operand: `+` between two `Substrate` values and `*` by a scalar build `Substrate.Add` / `Substrate.Weight` <Since v="2.0.0" /> (1.x refused both); any other operator | `DSH5293` |
| 3 | The widths agree: the result is as wide as the widest operand, a scalar operand spreads to that width, and a narrower vector does not | `DSH4226` |
| 4 | For `/`: not both operands integer constructor calls | `DSH4243` — see [Integer division](#integer-division) |

An operator never narrows an operand: `float3 * float4` is `DSH4226`, so channels are never dropped
silently. Since <Since v="2.0.0" /> it does not widen one either: 1.x widened an operand to the width of
an "authoritative" value in some cases; operands are typed now, and the scalar spread is the only way
two widths meet.

There is no separate scalar-promotion step: a scalar operand is passed to the material node as-is and
Unreal replicates it, so `A * K` with `A` a `vec3` and `K` a `float` produces a single `Multiply` node.

### Result of a binary operator

| Property | Value |
| :-- | :-- |
| Node | `Add` / `Subtract` / `Multiply` / `Divide` |
| Width | the widest operand's |
| Kind | promoted as in HLSL — an `int` with a `float` is a `float`; in the graph every value is a float |
| All-constant operands | folded into one `Constant` node by the constant-folding pass <Since v="2.0.0" /> |

## Unary operators

| Form | Lowering | Node cost | Result |
| :-- | :-- | :-- | :-- |
| `+x` | identity | none | `x` unchanged |
| `-x` | `Multiply(x, Constant(-1))` | one `Multiply` and one `Constant` holding `-1` | the type of `x` |

`!x` is `DSH2200`, `~x` is `DSH2201`, `++x` and `--x` are `DSH2207`.

A negated constant is folded: `-2.0` becomes one `Constant` holding `-2` <Since v="2.0.0" />, as does any
arithmetic over constants. See [Constant folding](#constant-folding).

## Integer division

`/` is the only operator with an extra type rule: `DSH4243` when **both** operands are integer
constructor calls (`int`, `int2..4`, `ivec2..4`, `uint`, `uint2..4`, `uvec2..4`). A material graph has
no integer division, so the compiler refuses to pick between HLSL's truncating answer and the graph's
fractional one.

Every other `/` is the graph's float division, as in 1.x, which typed every number literal float —
even where both sides are integers to the compiler: an integer literal (`7`), an `int` / `uint`
variable or property (legacy rule L27). [`dsc migrate`](/en/docs/language-v2/migrate) writes such a
division as `float(7) / 2`, because a `.dss` refuses every `/` between integers.

| Expression | Result |
| :-- | :-- |
| `int(7) / int(2)` | `DSH4243` |
| `int(7) / 2` | `3.5` (2.0.0 – 2.1.0 refused it with `DSH4243`) |
| `7 / 2` | `3.5` (2.0.0 – 2.1.0 refused it with `DSH4243`; restored in 2.1.1) |
| `7.0 / 2` | `3.5` |
| `float(int(7)) / int(2)` | `3.5` — one operand is a float |
| `int a = 7; int b = 2; a / b` | `3.5` (2.0.0 – 2.1.0 refused it with `DSH4243`) |

<Callout type="info">
`int`, `uint`, `bool` and `half` are kinds of their own to the compiler, and this rule is what the
difference is for. In the generated graph every one of them is a float — there is no integer
arithmetic and no truncation.
</Callout>

## Literals

Since <Since v="2.0.0" /> a 1.x `Graph` body is read by the DreamShaderLang 2.0 lexer: the token rules
below are the 2.0 ones, and the few 1.x readings that differ are refused with a code whose message says
what 1.x did.

### Numeric literals

<Synopsis>
```c
<number-literal> := { <digit> | . } … [ { e | E } [ { + | - } ] <digit> … ] [ <suffix> … ]
<suffix>         := { f | F | h | H | u | U | l | L }
```
</Synopsis>

A literal without a fraction, an exponent or a float suffix is an **integer** to the compiler — `int`,
or `uint` with a `u` <Since v="2.0.0" />; every other one is a `float` (`half` with an `h`). In the
generated graph every literal is the same thing: a 1-component float `Constant`.

| Written | Kind | Value | Result |
| :-- | :-- | :-- | :-- |
| `1` | `int` | 1.0 | `Constant`, 1 component |
| `1.0` | `float` | 1.0 | the **same** `Constant` node as `1` |
| `.5` | `float` | 0.5 | `Constant` — a leading `.` is legal |
| `1.` | `float` | 1.0 | `Constant` — a trailing `.` is legal |
| `1e-3` | `float` | 0.001 | `Constant` |
| `2.5E+2` | `float` | 250.0 | `Constant` |
| `0.55f` | `float` | 0.55 | `Constant` |
| `0.5h` | `half` | 0.5 | `Constant` |
| `3u`, `3ul` | `uint` | 3.0 | `Constant` — an unsigned integer <Since v="2.0.0" /> |
| `0.5.5` | — | — | `DSH2105` (1.x silently read 0.5) |
| `0x10` | — | — | `DSH2222` — a hexadecimal literal, which 1.x never read as one |
| `1.0fx` | — | — | `DSH2105` — the letters belong to the number |

Lexing details:

- A number is one token: digits, at most one `.`, at most one exponent, then suffix letters. Anything
  still glued to it — another `.`, letters, digits after a suffix — belongs to the same token and makes
  it `DSH2105` (1.x kept the longest valid prefix and dropped the rest). So `0.5.5`, `0..5`, `1abc` and
  `1.0fx` are errors, not numbers.
- An exponent needs digits: `1e` and `1e+` are `DSH2105`.
- A float suffix letter together with an integer one (`1fu`), or an integer suffix on a literal with a
  fraction or an exponent (`1.0u`, `1e3l`), is `DSH2105`.
- There is no binary or octal notation, and no digit separators.
- A leading `-` is not part of the literal; it is unary minus, and a negated literal folds into one
  `Constant`.

### String literals

A string literal is tokenized with escapes decoded, and **never evaluates to a value**. It is legal only
where an argument handler reads the literal *text*: a named `UE.*` / `Substrate.*` argument that sets a
property of the node, an `Output=` / `OutputName=` selector, or a `Path(…)` asset reference. Anywhere a
value is wanted it is `DSH4202`.

| Escape | Produces |
| :-- | :-- |
| `\n` | line feed |
| `\r` | carriage return |
| `\t` | tab |
| `\"` | `"` |
| `\\` | `\` |
| `\0` | nothing — the character is dropped |
| `\` + any other character | `DSH2104` <Since v="2.0.0" /> (1.x dropped the backslash) |

```c
vec4 Scene = UE.SceneTexture(Id = "PostProcessInput0");   // fine
float x    = "0.5";                                       // DSH4202
```

A string never spans lines. One with no closing `"` before the end of its line is `DSH2103`
<Since v="2.0.0" /> (1.x read on to the end of the input), and the rest of the file is still read and
reports its own errors.

### Boolean literals

`true` and `false` <Since v="1.5.0" /> are read as literals while the line is parsed, in any case, before
any name is looked up <Since v="2.0.0" /> (1.x resolved them after variables and properties). They are a
1-component `bool`, and the node is a `Constant` holding 1 or 0 <Since v="2.0.0" /> (1.x built a
`StaticBool`); equal constants are one node.

<Callout type="warn">
Because `true` / `false` are read **before** any name, a Graph variable or a declared property named
`True` or `False`, in any case, cannot be read: every use of the name is the literal. Avoid those names.
</Callout>

## Identifier resolution

Since <Since v="2.0.0" /> a name is looked up in two stages: the legacy front end reads a few 1.x
spellings while it parses (the boolean literals, type names, `N::F`, the 1.x call shorthands and the
properties that become nodes), and the 2.0 binder resolves everything else, as it does for a `.dss`.
The binder is **case-sensitive**; a name that matches only in another case is used through legacy rule
L19, with a warning.

| Order | Stage | Surface | Case | Result |
| --: | :-- | :-- | :-- | :-- |
| 1 | parse | The boolean literals `true` / `false` | insensitive | a 1-component bool value |
| 2 | parse | A type name — `float3`, `vec3`, `half`, `Texture2D`, … | insensitive | a type, which is no value: `DSH4204` |
| 3 | parse | A property whose type is a parameter node (`TextureSampleParameter2D`, `ChannelMaskParameter`, …), except `StaticSwitchParameter` | insensitive | the property's node, written out at this read |
| 4 | bind | A Graph variable — a declaration of the body, an `Outputs` declaration of a `Shader` — innermost block first | sensitive | the variable |
| 5 | bind | A parameter of the function: an input or output of a `ShaderFunction`, or `Base`, the material a `Shader` builds | sensitive | the parameter |
| 6 | bind | A file-scope declaration: a scalar, vector, texture or static-bool property | sensitive | the material parameter |
| 7 | bind | **Exactly one** of 4–6 that matches when case is ignored | insensitive | that one, with the warning `DSH5275` (legacy rule L19) |
| 8 | — | no match | — | `DSH4200`; `UE` or `Substrate` alone is `DSH4203` |

Steps 1–3 run before any variable is known, so they win over a variable of the same name. Step 7 needs
a unique match: when two declarations match ignoring case, neither is chosen and the name is `DSH4200`.
A Graph variable named like a scalar, vector, texture or static-bool property wins from its declaration
on, and the declaration says so with the warning `DSH4251`.

<Callout type="info">
A `StaticSwitchParameter` property deliberately does **not** resolve as a bare identifier — it needs its
two branches. Reading one by name is `DSH4200`; use the call form. See
[Calls](/en/docs/graph/calls#staticswitchparameter).

A name written in another case than its declaration **is** that declaration: `float3 Color = …;`
followed by `color = …;` writes `Color` <Since v="2.0.0" /> (1.x created a second entry named `color`).
</Callout>

The lookup order for call names is on [Calls](/en/docs/graph/calls#dispatch-order).

## Constructors

<Synopsis>
```c
<constructor-call> := <constructor-name> ( <expression> [ , <expression> ] … )
```
</Synopsis>

The parser reads a constructor name as a **type** <Since v="2.0.0" />: the call never reaches the
function lookup, and the binder checks it as it checks a `.dss` constructor. Names are matched
case-insensitively (`FLOAT3(…)` works). The component count is the number at the end of the name; a
name without one, or with `1`, is a scalar.

| Family | Names | Kind |
| :-- | :-- | :-- |
| HLSL float | `float` `float1..4` | float |
| HLSL half | `half` `half1..4` | half — behaves exactly like `float` |
| GLSL float vector | `vec2..4` | float |
| Signed integer | `int` `int1..4` `ivec2..4` | **int** |
| Unsigned integer | `uint` `uint1..4` `uvec2..4` | **uint** |
| Boolean | `bool` `bool1..4` `bvec2..4` | bool |
| double | `double` `double1..4` | double; a float in the graph like every number |
| `StaticBool` | `StaticBool` | read as `bool`, as in a declaration |

Since <Since v="2.0.0" /> the parser takes every spelling the HLSL type grammar has, so `int1`, `uint1`,
`bool1`, `double*` and `StaticBool` are constructors too. The matrix spellings (`float2x2` …
`float4x4`, `mat2`, `mat3`, `mat4`) are types, but the graph has no matrix value: `DSH4361`.

Names that do not exist: `vec1`, `ivec1`, `uvec1`, `bvec1` (the GLSL families start at 2); `hvec2..4`,
`dvec2..4`; the removed aliases `Scalar`, `Vector`, `Color`. They lex as ordinary identifiers and fall
through to the function lookup — `DSH4208` unless a function of that name is declared.
`MaterialAttributes`, `Substrate`, the texture types and `SamplerState` are type names too, but no value
of them can be constructed: `Texture2D(…)` is `DSH4223`.

<Callout type="warn">
**Constructor names shadow everything.** A constructor name is read as a type while the call is parsed —
before `UE.*`, `Substrate.*`, math builtins, parameters and all user declarations. A `Function`,
`GraphFunction`, `ShaderFunction` or `VirtualFunction` named `float3`, `int`, `bool4` or `vec2` can be
declared without a diagnostic but can **never be called** — every call site builds a constructor.
Rename it.
</Callout>

The integer kind does one thing: `/` is refused when both operands are integer constructor calls
(`DSH4243`), as in 1.x. It does not truncate, round or clamp — `int(7.9)` is 7.9. The kind comes from
the constructor's own name, so wrapping it in a non-integer constructor clears it: `float(int(7))` is a
float.

### Argument rules

The call and its arguments are checked first; every check that fails is reported:

| # | Condition | Behaviour |
| --: | :-- | :-- |
| 1 | Any argument is named (`float3(x = 1.0)`) | `DSH4225` |
| 2 | No argument at all (`float3()`) | `DSH4221` |
| 3 | An argument is not a number or a bool — a texture, a `MaterialAttributes` or `Substrate` value — or is a matrix | `DSH4226` |

Then, with `N` the constructor's component count:

| # | Case | Behaviour | Nodes |
| --: | :-- | :-- | :-- |
| 4 | exactly one argument, with `N` components (a scalar for `N == 1`) | the argument is returned **unchanged**; only its kind changes | none |
| 5 | `N > 1`, exactly one argument, a scalar | **broadcast**: the scalar is wired where the value is read, and the material node replicates it <Since v="2.0.0" /> (1.x built an `AppendVector` chain) | none; one `ConstantNVector` when the scalar is constant |
| 6 | otherwise | the arguments' component counts must sum to **exactly** `N` | one `AppendVector` per argument after the first |
| 7 | the sum is not `N` | `DSH4222` | — |

| Call | Total | Valid | Result |
| :-- | :-- | :-- | :-- |
| `float4(rgb, 1.0)` | 3 + 1 | yes | `float4` |
| `float4(uv, uv)` | 2 + 2 | yes | `float4` |
| `float3(x, yz)` | 1 + 2 | yes | `float3` |
| `vec3(0.5)` | scalar broadcast | yes | `(0.5, 0.5, 0.5)` |
| `float3(rgba)` | 4 | **no** | `DSH4222` |
| `float3(uv)` | 2 | **no** | `DSH4222` |
| `float(rgb)` | 3 | **no** | `DSH4222` |
| `float3()` | 0 | **no** | `DSH4221` |

<Callout type="info">
A constructor **never narrows** and never zero-fills — in a 1.x source either. `float3(rgba)` is an
error, not a truncation: write `rgba.rgb`. `float3(uv)` is an error too: write `float3(uv, 0.0)`.
Widening happens only from a scalar; narrowing only at the places listed under
[Conversions](#conversions). An output selector (`Output=`, `OutputIndex=`) on a constructor is
`DSH5253`.
</Callout>

### Constant folding

When every argument is a constant, the whole call is one constant node: a `Constant` /
`Constant2Vector` / `Constant3Vector` / `Constant4Vector`. A constant is a numeric literal, a negated
one, a `const` property, a variable that holds one, or any arithmetic on constants: the folding pass
folds operators, constructors, swizzles and builtins whose operands are all constants
<Since v="2.0.0" />.

| Written | Folded to |
| :-- | :-- |
| `vec2(0.5, 1.0)` | `Constant2Vector(0.5, 1.0)` |
| `vec3(0.5)` | `Constant3Vector(0.5, 0.5, 0.5)` — the broadcast folds too |
| `float4(1.0, 2.0, 3.0, -1.0)` | `Constant4Vector(1, 2, 3, -1)` |
| `int3(1, 2, 3)` | `Constant3Vector(1, 2, 3)` <Since v="2.0.0" />; still an `int3` to the compiler |
| `vec3(K, 0.0, 0.0)` | not folded when `K` is a parameter — two `AppendVector` nodes |

A folded value agrees with what the graph node would compute: constant `sin` and `cos` take cycles, as
the Sine and Cosine nodes with their default `Period = 1` do, so `sin(0.25)` and `sin(T)` with
`T = 0.25` are both 1 <Since v="2.1.2" />; `round` rounds a halfway value to even <Since v="2.1.2" />. See
[Math Builtins](/en/docs/builtins/math).

Equal constants are one node: `vec3(0.5)` written five times yields one `Constant3Vector`.

## Swizzles

<Synopsis>
```c
<swizzle>  := <expression> . <channels>
<channels> := <channel> [ <channel> ] [ <channel> ] [ <channel> ]
<channel>  := { x | y | z | w | r | g | b | a }
```
</Synopsis>

| Characters | Channel index |
| :-- | --: |
| `x`, `X`, `r`, `R` | 0 |
| `y`, `Y`, `g`, `G` | 1 |
| `z`, `Z`, `b`, `B` | 2 |
| `w`, `W`, `a`, `A` | 3 |

Exactly two sets exist: `xyzw` and `rgba`. There is no `stpq` set and no `uv` set — `.uv` is `DSH4230`.
Channel characters are matched case-insensitively. **Mixing the two sets in one swizzle is `DSH4230`**
<Since v="2.0.0" /> (1.x accepted `.xg` as `.xy`).

### Length and bounds

| Rule | Violation |
| :-- | :-- |
| One to four channel characters | `DSH4230` |
| Every character must be a channel letter | `DSH4230` |
| Every channel index must be **less than** the base value's component count | `DSH4230` |
| One set per swizzle | `DSH4230` |

| Base | Swizzle | Result |
| :-- | :-- | :-- |
| `float4` | `.rgb` | `float3` |
| `float3` | `.a` | error — channel 3 ≥ 3 components |
| `float2` | `.xyz` | error |
| `float` | `.x`, `.r` | the base value |
| `float` | `.xx`, `.rrr` | replicated to `float2` / `float3` |
| `float` | `.y`, `.g`, `.a`, … | **error** |

<Callout type="warn">
**A scalar does not splat through an out-of-range channel.** `Roughness.yz` on a scalar parameter is
`DSH4230`, not a two-component broadcast. To broadcast a scalar, repeat channel 0 (`Roughness.xx`), use a
constructor (`float2(Roughness)`), or rely on scalar widening at an assignment.
</Callout>

### Lowering

Since <Since v="2.0.0" /> a swizzle is a node: the generator never puts a channel mask on a connection.
Four cases, tried in this order:

| # | Applies when | Nodes created | Result |
| --: | :-- | :-- | :-- |
| 1 | The source node publishes exactly the selected channels as an output pin — `.rgb` or `.a` of a texture sample, `.rgb` or `.r` of a vector parameter | **none** | that pin is read |
| 2 | The channel indices are **strictly increasing with no repeats** | one `ComponentMask` | the selected channels |
| 3 | Base has 2–4 components and the mask is reordered or repeated | one single-channel mask per distinct channel (or its pin, by case 1), then N−1 `AppendVector` | the pieces concatenated |
| 4 | Base has 1 component and every channel is in range | N−1 `AppendVector` (none for one character) | the scalar replicated N times |

An identity mask — every channel of the value, in order: `.x` on a `float`, `.rgb` on a `float3` — is no
node in a `.dss`. In a 1.x source it is kept as a `ComponentMask`, because 1.x masked the connection
whatever width the value was declared with.

| Swizzle | Channels | Case | Node cost |
| :-- | :-- | :-- | :-- |
| `.r` / `.x` | 0 | 2 | 1 `ComponentMask` |
| `.rg` / `.xy` | 0,1 | 2 | 1 `ComponentMask` |
| `.ga` | 1,3 | 2 — increasing, gaps allowed | 1 `ComponentMask` |
| `.gr` | 1,0 | 3 | 2 `ComponentMask`, 1 `AppendVector` |
| `.bgr` | 2,1,0 | 3 <Since v="1.3.3" /> | 3 `ComponentMask`, 2 `AppendVector` |
| `.xxx` | 0,0,0 | 3 | 1 `ComponentMask`, 2 `AppendVector` |
| `.rr` on a `float` | 0,0 | 4 | 1 `AppendVector` |

Case 1 replaces a `ComponentMask` in this table by a pin wherever the source node has one. Every node is
counted once however often the swizzle is written: equal nodes are merged.

<Callout type="info">
**Why there are no inline masks any more.** The material graph editor trusts a connection mask only when
it can resolve it back to a named pin; in 1.8.0 that silently turned `CustomStencil.r` into `InvSize` on
nodes such as `SceneTexture`. Since <Since v="2.0.0" /> every mask is a real node or a real pin, and the
editor's Apply / Save never rewrites a connection.
</Callout>

### Composition

A swizzle of an already-swizzled value re-maps through the existing mask, so the numbering is always
relative to the value being swizzled.

| Written | Meaning |
| :-- | :-- |
| `v.rgb.b` | channel 2 of `v` |
| `v.ga.r` | channel 1 of `v` — `.ga` selects 1,3, then `.r` picks entry 0 |
| `v.ga.g` | channel 3 of `v` |
| `v.bgr.r` | channel 2 of `v` |

A mask of a mask folds into one mask while the result stays ascending, so `v.rgb.rg` is one
`ComponentMask` (or one pin) on `v`. Selecting an entry the outer list does not have is a bounds failure
against the *swizzled* width: `v.ga.b` is `DSH4230`. A swizzle of constants is folded:
`vec4(1.0, 2.0, 3.0, 4.0).yx` is one `Constant2Vector(2, 1)`.

Because `.` is an ordinary postfix operator, any call result can be swizzled directly:

```c
float u  = UE.TexCoord().x;
vec3  c  = SampleTexture2D(Albedo, uv).rgb;
vec2  yx = vec4(1.0, 2.0, 3.0, 4.0).yx;
float m  = MyFunction(A, B).r;
```

On a call of a `Function`, `GraphFunction`, `ShaderFunction` or `VirtualFunction`, a member named like
one of the function's outputs selects that output; when the function returns nothing, **any** member is
read as an output name (legacy rule L3b), and one that is no output is `DSH5280`. See
[Calls](/en/docs/graph/calls#output-selection). On a `UE.*` node with several outputs a member names an
output; a swizzle is allowed only where the outputs are channel views of one value, as on a texture
sample.

### Non-swizzlable bases

| Base value | Behaviour |
| :-- | :-- |
| `MaterialAttributes` | not a swizzle — the member is read as a material attribute. See [Statements](/en/docs/graph/statements#materialattributes-member-writes) |
| Texture object | `DSH4206`: a member of a texture is a sampling method, which has to be called |
| `Substrate` | `DSH4207`: the value has no such member |

## Conversions

Conversion is not written by the author; it is applied wherever a value meets a typed place. Since
<Since v="2.0.0" /> every value has a **type**: a number of 1–4 components of one kind (`float`, `half`,
`double`, `int`, `uint`, `bool`), a texture of one texture type, `SamplerState`, `MaterialAttributes` or
`Substrate`. What a 1.x source may do and a `.dss` may not — cut a wider value down — is legacy rule
L22, and it says so.

### Where it applies

| # | Site | Type taken from | Code when nothing fits |
| --: | :-- | :-- | :-- |
| 1 | Declaration with an initializer — `float3 c = A;` | the declared type | `DSH4228` |
| 2 | Assignment to a Graph variable — `c = A;` | the variable's declared type | `DSH4228` |
| 3 | Assignment to a name matching an `Outputs` declaration — `Color = A;` | the output's declared type | `DSH4228` |
| 4 | `MaterialAttributes` member write | the attribute's own type | `DSH4228` |
| 5 | A function's input argument | the input's declared type | `DSH4226` |
| 6 | A `UE.*` / `Substrate.*` pin, the coordinates of a texture sample | the pin's type in the engine catalog | `DSH5214` |
| 7 | An `if` condition | one true-or-false value | `DSH4260` |
| 8 | An `Outputs` binding of a `Shader` — `Base.EmissiveColor = Color;` | the material attribute's type | `DSH4228`, and never a cut |
| 9 | Operands of `+ - * /` | the widest operand: a scalar spreads to it, nothing else changes width | `DSH4226` |

An assignment to a name that matches no declaration in any case declares it with the value's own type
(legacy rule L26, info `DSH5292`); there is nothing to convert to. An `if` that assigns a variable in
both branches merges two values of the variable's declared type, so the merge itself converts nothing.

### Rule order

| # | Value → place | Behaviour | Nodes |
| --: | :-- | :-- | :-- |
| 1 | The same type | passes through **unchanged** | none |
| 2 | A number of the same width and another kind (`int` → `float`, `float` → `bool`, …) | the kind changes; the value in the graph does not | none |
| 3 | **Widening from a scalar** — a scalar into a wider number | broadcast: the scalar is wired where the value is read, and the material node replicates it <Since v="2.0.0" /> | none; one `ConstantNVector` when the scalar is constant |
| 4 | A narrower vector into a node's pin (2 into a `float3` pin, …) | taken as it is: what a node does with fewer components is the node's business | none |
| 5 | **Narrowing**, in a 1.x source — a wider vector into a narrower place | its leading components (`r`, `rg`, `rgb`), said by the info `DSH5289` <Since v="2.0.0" /> | a `ComponentMask`, or the output pin the source node has for exactly those channels; none at a node's pin |
| 6 | A node with several outputs into a number | its default output, when that output's type fits; in a 1.x source, a node whose first output the catalog gives no width is read as that output, and so is **any node passed straight to a node's pin** (info `DSH5287`; 2.0.0 – 2.1.0 refused the second case <Since v="2.1.1" />); otherwise `DSH5201` | none |
| 7 | Anything else | rejected with the site's code | — |

The second half of rule 6 means that `UE.TransformPosition(UE.WorldPosition(), …)` builds again:
`UE.WorldPosition()` at a pin is its first output, `XYZ`; `dsc migrate` writes `UE.WorldPosition().XYZ`.

Input width down the side, expected width across the top, in a 1.x source:

| input \ expected | 1 | 2 | 3 | 4 |
| :-- | :-- | :-- | :-- | :-- |
| **1** | unchanged | broadcast, no node | broadcast, no node | broadcast, no node |
| **2** | `.r`, `DSH5289` | unchanged | **error** | **error** |
| **3** | `.r`, `DSH5289` | `.rg`, `DSH5289` | unchanged | **error** |
| **4** | `.r`, `DSH5289` | `.rg`, `DSH5289` | `.rgb`, `DSH5289` | unchanged |

At a node's pin the two errors in the matrix are accepted (rule 4), and a cut makes no node.

Across kinds ("error" is the site's code):

| expected \ input | number | MaterialAttributes | Substrate | texture |
| :-- | :-- | :-- | :-- | :-- |
| **MaterialAttributes** | error | pass | error | error |
| **Substrate** | error | error | pass | error |
| **Texture(T)** | error | error | error | pass if the texture type is `T`; a pin that takes any texture takes any |
| **Number(N)** | matrix above | error | error | error |

A texture converts only to its own texture type: `Texture2D`, `TextureCube`, `Texture2DArray`,
`Texture3D` and `VolumeTexture` are five types, and `SamplerState` is a type of its own, not a texture
<Since v="2.0.0" />. A `TextureCube` never converts to a `Texture2D`.

### Narrowing

In a 1.x source a value wider than its place keeps its leading components (legacy rule L22). The cut is
no longer silent <Since v="2.0.0" />: each one is the info `DSH5289`, so `dsc check` lists them and
`dsc migrate` writes the swizzle.

```c
vec4   Src = vec4(0.1, 0.2, 0.3, 0.4);
float3 Rgb = Src;      // Src.rgb — DSH5289; channel A is dropped
float  R   = Src;      // Src.r   — DSH5289
```

Writing the swizzle explicitly (`float3 Rgb = Src.rgb;`) documents the intent, builds the same node and
makes the info go away.

Narrowing applies **only** at sites 1–7 above. It is deliberately not applied to binary operator
operands (`DSH4226`), constructor arguments (`DSH4222`), swizzle bounds (`DSH4230`), an `Outputs`
binding of a `Shader` such as `Base.Opacity = Color4;` (`DSH4228`, the one place 1.x refused to cut
too), or a `.dss` source.

### Widening

The **only** widening rule is scalar broadcast: a 1-component value meets a wider place without a node;
the scalar itself is connected wherever the value is read, and the material node replicates it
<Since v="2.0.0" /> (1.x built an `AppendVector` chain). A constant scalar is folded into a
`ConstantNVector`.

There is **no** zero-fill and **no** partial widening. `float3 v = SomeFloat2;` is `DSH4228`; use a
constructor to say what the extra channels contain: `float3 v = float3(SomeFloat2, 0.0);`. The one place
a narrower vector is accepted is a node's pin (rule 4).

### Float, int and bool

The compiler knows the kind of every number <Since v="2.0.0" />; the generated graph does not, because
every value in a material graph is a float. A change of kind therefore changes nothing in the graph.

| Token family | What it means for conversion |
| :-- | :-- |
| `float`, `float1..4`, `half`, `half1..4`, `vec2..4` | 1 / 2 / 3 / 4 components of kind `float` or `half` |
| `int`, `int2..4`, `ivec2..4` | kind `int` — no truncation, no rounding |
| `uint`, `uint2..4`, `uvec2..4` | kind `uint` — no range clamping, no sign handling |
| `bool`, `bool2..4`, `bvec2..4` | kind `bool` — no normalisation to 0/1 |
| `StaticBool`, `StaticBoolParameter` | read as `bool`, 1 component |

- `int x = 7.9;` stores 7.9; use `floor(…)` or `trunc(…)` for truncation.
- `bool b = 0.5;` stores 0.5; there is no conversion to 0 or 1 — compare to get one.
- An explicit conversion follows the same rule: `int(0.5)` and `bool(0.5)` keep 0.5, in a constant too
  <Since v="2.1.2" /> — earlier versions truncated while folding constants, which could flip a constant
  condition. A conversion inside a `Function` body is an HLSL conversion.
- Assigning a `float4` to an `int3` narrows exactly like `float4` → `float3` (`DSH5289`).
- The kind matters in one place: `/` between two integer constructor calls is `DSH4243`; see
  [Integer division](#integer-division).

### Authoritative component counts

Since <Since v="2.0.0" /> **there are none**. 1.x let some values — a constant-folded constructor, `dot`,
the `UE.*` builtins of a known-width table — carry an "authoritative" width that overrode a declaration
and steered operators. Every value now has the width of its type:

| Value | Width |
| :-- | :-- |
| A variable | the width it is declared with — always honoured |
| A literal | 1 |
| A constructor, folded or not | its type's |
| A builtin | its operands' widest, or what the builtin returns (`dot`, `length`, `distance`: 1) |
| A `UE.*` / `Substrate.*` node output | what the engine catalog gives that output; an output the catalog gives no width follows the node's widest input, or, when no input is wider than a scalar, the place the value goes |
| A swizzle | its number of channels |

So `float2 dir = UE.CameraVectorWS();` is a `float2` — the leading two components, `DSH5289` — where 1.x
stored three. Two operands of different widths meet only through the scalar broadcast; anything else is
`DSH4226`.

## Node reuse

Since <Since v="2.0.0" /> reuse is a pass over the compiler's intermediate graph, run once the whole asset
has been built, rather than a cache the 1.x generator consulted while it built nodes. The rule is the same
— two nodes with the same class and the same arguments are one node — but it applies to **every** node.

The passes run over the graph of **one** generated asset: one `Shader`, or one `ShaderFunction` /
`ShaderLayer` / `ShaderLayerBlend`. A material and two function assets in one `.dsm` are three
independent graphs, and nothing is shared between them.

| Order | Pass | What it does |
| --: | :-- | :-- |
| 1 | prune | drops nodes nothing reads, before anything is merged |
| 2 | fold | an operator, builtin, constructor or swizzle whose operands are all constants becomes one constant |
| 3 | swizzles | a mask of a mask becomes one mask while it stays ascending; an identity mask is no node (except in a 1.x source) |
| 4 | dedupe | merges equal nodes |
| 5 | prune | drops what no output reaches any more; a parameter nothing reads is the info `DSH4390` |

Passes 2–4 repeat, at most four times, until a round changes nothing. The pass is **not** scoped to a
block: a subexpression written in the then-branch and again in the else-branch, or after the `if`, is one
node.

Two nodes are one node when every part of them is equal: the operation (an operator, a builtin, a
constant, a parameter, a reflected `UE.*` / `Substrate.*` node, a Custom node, a function call), the
class, the outputs (count, names and types — a bool constant and a float constant differ), the properties
(numbers to 9 significant digits), the operands in order (so `a * b` and `b * a` are two nodes) and the
input pins as a set (so the order arguments were written in does not matter). The comparison is on
**nodes**, never on text: a variable stands for the node it holds, so re-assigning a variable between two
textually identical expressions gives two nodes, while `F_Tint(a, b)` and `F_Tint(Color = a, Tint = b)`,
or `1` and `1.0`, are one node.

What 1.x never shared and is now merged when equal:

| Construct | 1.x | Now |
| :-- | :-- | :-- |
| `Function` and `GraphFunction` calls | a fresh `Custom` node per call site | one node per distinct argument list |
| `UE.Expression` of a Custom class | never shared | shared when the code and the inputs are equal |
| `UE.TexCoord`, `UE.Time`, `UE.Panner`, `UE.TransformVector`, `UE.TransformPosition` and the no-argument state reads | a node per call site | one node per distinct argument list |
| `UE.CollectionParam` / `UE.CollectionParameter` | a node per call site | one node per collection and parameter |
| `MakeMaterialAttributes`, `SetMaterialAttributes` and attribute reads | a node per declaration, write and read | shared when equal |
| `If` | one node per merged variable per `if` | shared when the condition and both values are equal |
| `StaticSwitchParameter` calls | never shared | one node per distinct pair of branches |
| Parameter and property nodes | once per scope, again after an `if` | one node per parameter and argument list |

Never merged: statement-like nodes (the material's output, a function's outputs, a custom-output node such
as `UE.DreamPassOutput`), function inputs (`FunctionInput`), and two nodes that differ in one property,
pin or operand (`UE.TexCoord(Index = 0)` and `UE.TexCoord(Index = 1)`; a parameter's pin call and a bare
read of it).

<Callout type="info">
So: every occurrence of the same numeric value in one asset is **one** `Constant` (`1` and `1.0`, `0.5`
and `.5`); the same `-x` written twice is one `Multiply`, while two different negations each have a
`Constant(-1)` of their own (1.x shared one); `UE.TexCoord(Index = 0)` written five times is **one**
`TextureCoordinate` (1.x made five); a parameter first read inside a branch and read again after the `if`
is one node (1.x left a duplicate). Layout is computed on the merged graph, so a merged node has one place
and leaves no gap.
</Callout>

## Example

```c
Shader(Name="Docs/M_Expressions")
{
    Properties {
        vec3 A = vec3(1.0, 0.5, 0.2);
        vec3 B = vec3(0.1, 0.2, 0.3);
        float K = 2.0;
    }
    Settings { Domain = "UI"; ShadingModel = "Unlit"; }
    Outputs { vec3 Color; Base.EmissiveColor = Color; }
    Graph {
        vec3 Sum    = A + B;
        vec3 Diff   = A - B;
        vec3 Scaled = A * K;
        vec3 Ratio  = A / K;
        vec3 Neg    = -Scaled;
        Color = (Sum + Diff - Scaled + Ratio) * 0.25 + Neg;
    }
}
```

```text
VectorParameter A, VectorParameter B, ScalarParameter K   (property nodes)
Add(A, B)                                        -> Sum
Subtract(A, B)                                   -> Diff
Multiply(A, K)                                   -> Scaled
Divide(A, K)                                     -> Ratio
Multiply(Scaled, Constant(-1))                   -> Neg
Add / Subtract / Add chain, Multiply(..., 0.25), Add(..., Neg)
```
