---
title: Calls
description: Calling Function, GraphFunction, ShaderFunction, VirtualFunction and parameter pins from a Graph block — dispatch order, value form, statement form, arguments and output selection.
---

Anything written as `Name(...)` in a `Graph` body is a call. Several declaration kinds and two kinds of
parameter can be called, plus the builtins and constructors that are resolved ahead of them. Since
<Since v="2.0.0" /> a `.dsm` / `.dsf` is read by the legacy front end and bound by the 2.0 binder: the
call spellings on this page build the same nodes they did, and where a 1.x call reads differently from a
`.dss` call, a numbered legacy rule applies and says so with its own code. The `.dss` spelling of each is
on [`dsc migrate`](/en/docs/language-v2/migrate).

## Synopsis

<Synopsis>
```c
// value form — the call produces a value
<target> = <callee> ( [ <argument> [ , <argument> ] … ] ) ;

// statement form — the call writes into out targets
<callee> ( [ <input-argument> , ] … <out-target> [ , <out-target> ] … ) ;

<callee>     := <identifier> | <namespace> :: <identifier>
<argument>   := <expression> | <identifier> = <expression> | default
<out-target> := <identifier>
```
</Synopsis>

A positional argument after a named one is `DSH2158`, in every call <Since v="2.0.0" />.

## Callable kinds

<Wide>

| Kind | Value form | Statement form | Named arguments | Node produced |
| :-- | :-- | :-- | :-- | :-- |
| `Function` | yes — the return value, or the first `out` <Since v="2.0.0" /> | yes | yes <Since v="2.0.0" /> | `Custom` |
| `GraphFunction` | yes — as `Function` <Since v="2.0.0" /> | yes | yes <Since v="2.0.0" /> | `Custom` |
| `ShaderFunction` (same file) | yes, any output count | yes | yes | `MaterialFunctionCall` |
| `ShaderLayer`, `ShaderLayerBlend` | **not callable**: `DSH6208` <Since v="2.0.0" /> | — | — | — |
| `VirtualFunction` | yes, any output count | yes | yes | `MaterialFunctionCall` |
| `StaticSwitchParameter` property | yes | no | yes | `StaticSwitchParameter` |
| input-bearing parameter | yes | no | **only** named | the parameter's own node, configured |

</Wide>

A `ShaderFunction` of another file is reached through a `VirtualFunction` naming its asset: an `import`
brings in a `.dsh` header only, and a header holds no asset blocks.

`UE.*`, `Substrate.*`, math builtins, constructors and `SampleTexture2D` are call syntax too, but they are
resolved *before* any of the kinds above. See [UE.* Nodes](/en/docs/builtins/ue-nodes) and
[Math Builtins](/en/docs/builtins/math).

## Dispatch order

Call names are probed strictly in this order. The first surface that claims the name wins; later
surfaces are never consulted.

| Order | Stage | Surface | Case | Notes |
| --: | :-- | :-- | :-- | :-- |
| 1 | parse | `Path(…)` | insensitive | an asset reference, not a call |
| 2 | parse | a type name | insensitive | a constructor: see [Constructors](/en/docs/graph/expressions#constructors) |
| 3 | parse | `N::F` | — | read as the identifier `N_F`, then looked up from step 9 on |
| 4 | parse | a property whose type is a parameter node | insensitive | `StaticSwitchParameter`: the [static-switch call](#staticswitchparameter); the others: the [pin call](#input-pin-wiring) |
| 5 | parse | `SampleTexture2D` | **sensitive** | `UE.Expression(Class="TextureSample", …)`; anything but two positional arguments is `DSH5256` |
| 6 | parse | `BreakOutFloat2Components` … `BreakOutFloat4Components` with an output selector | insensitive | a swizzle of the first argument; see [below](#breakoutfloatncomponents) |
| 7 | parse | the 1.x `UE.*` shorthands — `UE.TexCoord`, `UE.Time`, `UE.SceneTexture`, `UE.StaticSwitchParameter`, … | insensitive | arguments are read the 1.x way, and one the shorthand never read is dropped with the warning `DSH5254` |
| 8 | bind | `UE.<Node>` / `Substrate.<Node>` | node name exact, then insensitive with the warning `DSH5276` | [UE.* Nodes](/en/docs/builtins/ue-nodes) and [Substrate](/en/docs/builtins/substrate) (UE 5.4+) |
| 9 | bind | a math builtin | sensitive | the HLSL spellings in [Math Builtins](/en/docs/builtins/math) |
| 10 | bind | `mix`, `fract`, `mod`, `inversesqrt` | sensitive | the GLSL spelling of a builtin: that builtin, with the warning `DSH5277` |
| 11 | bind | a `Function`, `GraphFunction`, `ShaderFunction` or `VirtualFunction` of this file or an imported header | sensitive | see below |
| 12 | bind | exactly one builtin, else exactly one function, that matches when case is ignored | insensitive | that one, with the warning `DSH5275` (legacy rule L19) |
| 13 | — | no match | — | `DSH4208` |

The `UE` in front of a node is compared exactly <Since v="2.0.0" />: `ue.TexCoord()` reads `ue` as an
undeclared name, `DSH4200`.

A builtin claims its name outright. A malformed `clamp(x)` is the builtin's arity error, `DSH4224`; there
is no user function of that name to fall through to, because declaring one is `DSH6206`
<Since v="2.0.0" />.

<Callout type="warn">
Shadowing only ever runs one way — an earlier surface hides a later one. A `Function` named `float3`,
`vec2` or any other type spelling declares fine but is **never called**: the name is read as a type while
the call is parsed. A `Function` named `SampleTexture2D` is never called either; the `SampleTexture2D`
rewrite compares exactly, so a `Function` named `sampletexture2d` *is* reachable by that spelling.
</Callout>

## Callee spellings

| Spelling | Resolves to |
| :-- | :-- |
| `Name` | the function declared under that name, compared **case-sensitively** <Since v="2.0.0" />. A name that matches exactly one function only when case is ignored resolves to it with the warning `DSH5275` |
| `Namespace::Name` | a `Function` / `GraphFunction` declared inside `Namespace(Name="Namespace")`. The parser reads `N::F` as the one identifier `N_F`, the name the function is declared under <Since v="2.0.0" />, so `N_F(…)` reaches it too; the bare `F` does not. There is no `using` and no unqualified fallback |
| `DreamShaderFn_Name` | no longer an alias of the function <Since v="2.0.0" />: `DSH4208` |
| trailing path segment | for a `ShaderFunction` declared as `Name="Functions/F_Tint"`, the segment after the final `/` — `F_Tint` — with every character that is not a letter, a digit or `_` replaced by `_`. A `VirtualFunction`'s `Name` has to be an identifier already (`DSH6311`) |

There is no overloading. One name declares one thing: a second function, property or struct of a name
already declared is `DSH4210`. The exception is a `ShaderFunction` block whose leaf name is taken by a
function declared before it — typically one from an imported header: the block's function is declared as
`<Name>_Asset` instead, and the asset keeps its name (info `DSH5290`). Two names that differ only in case
are two declarations <Since v="2.0.0" />; a call spelled like neither then has no unique case-insensitive
match and is `DSH4208`.

## Value form

```c
float L = Luma(BaseColor);
vec3  C = Common::ApplyTint(BaseColor, Tint);
vec3  N = F_Normal(uv, Output="Normal");
```

| Kind | Requirements |
| :-- | :-- |
| `Function`, `GraphFunction` | The value is the return value or, for a function with `out` parameters, its first `out` (legacy rule L3b) <Since v="2.0.0" /> (1.x refused a value call of a function with several outputs). Another output is read with an [output selector](#output-selection). Arguments fill the parameters in declaration order and by name: an input left without one is `DSH4217`, an argument past the last parameter `DSH4224`. The order counts `out` parameters too: an argument that lands on one receives that output, as in a statement call |
| `ShaderFunction`, `VirtualFunction` | The value is output 0 — the first declared output — unless an [output selector](#output-selection) picks another <Since v="2.0.0" /> (1.x required a selector when several outputs were declared). An input declared `opt` may be left out or passed `default` |

A `GraphFunction` call is one Custom node, like a `Function` call; the `UE.` calls lifted out of its body
become further inputs of that node, lowered with this call's arguments.

Calls with the same callee and the same arguments are one node; see
[Node reuse](/en/docs/graph/expressions#node-reuse). A call result is an ordinary postfix expression, so it
can be swizzled directly: `SampleTexture2D(Albedo, uv).rgb`.

## Statement form

```c
F_PulseTint(BaseColor, Tint, TintedColor, PulseAmount);
```

Multi-output `ShaderFunction` / `VirtualFunction` statement calls are available since
<Since v="1.3.5" />.

A call statement may call anything. A call whose value nothing receives — a builtin, a constructor, a
parameter — is accepted, and the node it makes is dropped because nothing reads it <Since v="2.0.0" />
(1.x refused such a statement). An expression statement that is neither a call nor an assignment is
`DSH2211` (`F(a).Out;`, `x;`).

How the arguments of a statement call to a function are read:

| Arguments | Read as |
| :-- | :-- |
| all positional; at least one per output and at most one per input and output | the last ones receive the outputs, one each, in declaration order — the return value first when the function has one; the ones before them are inputs, in order (legacy rule L5) |
| any named argument, or a count outside that range | matched to the parameters in declaration order and by name, as in a `.dss` call: too many is `DSH4224`, and an input or an output left without an argument is `DSH4217` |

In the first reading an input not covered must be declared `opt` or passed `default`, otherwise
`DSH4217`. Every declared output must receive a target — there is no way to discard one.

### Out-target rules

| Rule | On failure |
| :-- | :-- |
| An out target is something that can be assigned: a variable, or a member or swizzle of one <Since v="2.0.0" /> (1.x took a plain name only) | `DSH4239` |
| A name declared nowhere is declared here, as a local of the output's type (legacy rule L5) | info `DSH5283` |
| A declared variable has its type. A numeric output wider than the variable gives its leading components, and a scalar output fills it; anything else is refused | `DSH4218` |
| One variable named for two outputs | not reported |

<Callout type="info">
An out target spelled in another case than a declaration **is** that declaration, with `DSH5275` — not a
second variable <Since v="2.0.0" />. A name only becomes a new local when nothing is declared under it in
any case.
</Callout>

## Arguments

### Positional and named

| Callee | Positional | Named |
| :-- | :-- | :-- |
| `Function`, `GraphFunction`, `ShaderFunction`, `VirtualFunction` | fill the parameters in declaration order | match a parameter by name (for `Function` / `GraphFunction` since <Since v="2.0.0" />); another case resolves with `DSH5275`; no such parameter is `DSH4216` |
| input-bearing parameter | rejected: `DSH5259` | required: a pin of the node |
| `StaticSwitchParameter` | index 0 = true branch, index 1 = false branch | `True` / `A`, `False` / `B` |

Positional arguments come first and named ones after them; the reverse is `DSH2158`. A parameter given
twice — by position and by name, or by name twice — is `DSH4215`. In a statement call, a named argument
switches off the receivers-last reading (see [Statement form](#statement-form)).

Parameter names are compared exactly, with the `DSH5275` fallback above; a node's pin matches in another
case with the warning `DSH5276`. The names the 1.x front end reads itself — `Output`, `OutputName`,
`OutputIndex`, `True`, `False`, `A`, `B` — are matched ignoring case.

Every input argument is converted to the input's declared type: a wider value gives its leading
components with the info `DSH5289`, and one that does not fit is `DSH4226`. See
[Conversions](/en/docs/graph/expressions#conversions).

### `default`

<Since v="1.2.3" /> `default` is a bare identifier that holds the place of an input left out on purpose
(legacy rule L25). It is matched **case-sensitively** <Since v="2.0.0" />, and only while no variable of
that name is declared.

| Situation | Behaviour |
| :-- | :-- |
| `default` for an input of a `ShaderFunction` / `VirtualFunction` | the input pin is left unconnected; the function's own default applies |
| `default` for an input that is not `opt` | the same <Since v="2.0.0" /> (1.x refused it) |
| `default` in a `Function` / `GraphFunction` call | accepted <Since v="2.0.0" />; the Custom node gets no input for that parameter |
| `Default`, `DEFAULT` | an ordinary name: `DSH4200` when nothing of that name is declared |

Omitting a trailing optional input entirely has the same effect as passing `default`.

```c
float3 tinted = F_Tint(BaseColor, default, Output="OutColor");
```

## Output selection

`Output`, `OutputName` and `OutputIndex` are named arguments the 1.x front end reads itself: it removes
them from the call and selects the output instead, as `.Name` written after the call would. They work on
a call of any function kind (for `Function` and `GraphFunction` since <Since v="2.0.0" />) and on `UE.*`
calls.

| Argument | Accepts | Meaning |
| :-- | :-- | :-- |
| `Output` | a quoted name or an identifier | select the output of that name — exact first, then ignoring case with `DSH5275` |
| `OutputName` | the same | exact synonym of `Output` |
| `OutputIndex` | a whole-number literal, 0 or more | select by 0-based index: the outputs in declaration order, with a return value as output 0 |

```c
float value = F_MultiOutput(Input=Mask, Output="Height");
float other = F_MultiOutput(Input=Mask, OutputIndex=1);
```

| Rule | On failure |
| :-- | :-- |
| `Output` / `OutputName` and `OutputIndex` are mutually exclusive | `DSH5252` |
| `OutputIndex` must be a whole number of zero or more | `DSH5250` |
| `Output` / `OutputName` must be a quoted name or an identifier, not an expression | `DSH5251` |
| A constructor takes no selector | `DSH5253` |
| A parameter call takes no selector | `DSH5265` |
| The name must match an output of the function | `DSH5280`. On a function that returns a value, a name that is no output is read as a swizzle of the value instead (`DSH4230` when it is not one) |
| The index must be inside the outputs | `DSH5282` |
| A function with several outputs called with no selector | not an error <Since v="2.0.0" />: the call reads output 0 |
| The selected output must exist on the loaded asset — matched by name, then ignoring case, then (for a `VirtualFunction`) by declared position | `DSH8221`, when the asset is emitted |

<Callout type="warn">
A selector makes the call a value. It cannot stand in a statement call: the selected call is an
expression nothing receives, which is `DSH2211`.
</Callout>

`UE.Expression(…)` accepts the same three selectors; a name the node does not have is `DSH5201`, an index
past its outputs `DSH5282`. See [UE.Expression](/en/docs/builtins/ue-expression).

### `BreakOutFloatNComponents`

A call named `BreakOutFloat2Components`, `BreakOutFloat3Components` or `BreakOutFloat4Components` (any
case) whose first argument is positional and which carries an output selector is **read as a swizzle** of
that first argument. No `MaterialFunctionCall` node is made, and no function of that name is looked up
<Since v="2.0.0" />. The selected output names a channel, its letter in any case:

| Output name | Channel |
| :-- | --: |
| `x`, `r`, `"0"` | 0 |
| `y`, `g`, `"1"` | 1 |
| `z`, `b`, `"2"` | 2 |
| `w`, `a`, `"3"` | 3 |

`OutputIndex=` selects the same channel by index. The channel has to lie inside the width the name says
(0–1 for `BreakOutFloat2Components`). Otherwise — no selector, a named first argument, a channel past the
width — the call is an ordinary call of the function of that name. Both selectors at once are `DSH5252`.

## Calling a parameter

### Input-pin wiring

<Since v="1.4.1" /> A declared parameter whose node owns input pins may be "called" to wire those pins.
The front end writes **each** use of such a property — a call or a bare read — as its own
`UE.Expression(Class = "<type>", ParameterName = "<name>", …)` call, with the declaration's default and
metadata as arguments and the call's arguments on the pins <Since v="2.0.0" />. Uses with the same
arguments are one node after deduplication; a bare read and a pin call carry different arguments, so they
are two nodes that address the same material parameter. A texture-sample parameter is read through its
`RGBA` output.

Complete list of parameter node types that accept this form:

| | | |
| :-- | :-- | :-- |
| `ChannelMaskParameter` | `StaticComponentMaskParameter` | `TextureSampleParameter2D` |
| `TextureSampleParameter2DArray` | `TextureSampleParameterCube` | `TextureSampleParameterCubeArray` |
| `TextureSampleParameterVolume` | `TextureSampleParameterSubUV` | `RuntimeVirtualTextureSampleParameter` |
| `SparseVolumeTextureSampleParameter` | | |

Pin names are the node's own, as the engine catalog lists them; another case resolves with `DSH5276`.
Every argument must be named (`DSH5259`), and each value is checked against its pin like any `UE.`
argument (`DSH5214`).

<Callout type="warn">
Asset slots are not call arguments. The texture, curve or font a sampler parameter points at is set with
`[TextureSlot=Path(…)]`-style declaration metadata, which becomes a property argument of the node; a call
argument naming a property the declaration already sets is `DSH4215`. A name that is neither a pin nor a
property is `DSH5213`; when its value is a graph value it is the info `DSH5291` instead, and the pin is
connected by that name once the node exists (`DSH8212` if the node shows no such pin). See
[Properties](/en/docs/parameters/properties) and [Metadata](/en/docs/parameters/metadata).
</Callout>

```c
Properties = {
    TextureSampleParameter2D Albedo = Path(Game, "Textures/T_Albedo");
}

Graph = {
    vec2 UV  = UE.TexCoord(Index = 0);
    vec4 Tex = Albedo(Coordinates = UV);
}
```

### `StaticSwitchParameter`

<Since v="1.2.3" /> A `StaticSwitchParameter` property does **not** resolve as a bare identifier
(`DSH4200`) — it needs two branches, so it is readable only through the call form.

| Branch | Argument names, in lookup order |
| :-- | :-- |
| true | `True=`, then `A=`, then positional index 0 |
| false | `False=`, then `B=`, then positional index 1 |

Both branches must be present (`DSH5258`); any other argument is dropped with the warning `DSH5254`. The
call becomes a `UE.Expression(Class = "StaticSwitchParameter", …)` with the branches on its `A` and `B`
pins, which are checked like the pins of any `UE.` node <Since v="2.0.0" />.

```c
Properties = {
    StaticSwitchParameter UseDetail = true [
        Group="Switches";
        SortPriority=30;
    ];
}

Graph = {
    vec3 Albedo = UseDetail(True = DetailColor, False = BaseColor);
}
```

Because the switch is resolved at shader-permutation time rather than per pixel, it is the cheap
alternative to `if` when "which one" is a material setting rather than a computed value.

## Recursion and nesting

| Situation | Behaviour |
| :-- | :-- |
| A `GraphFunction` whose lifted `UE.` calls call it again, directly or through another function | `DSH6330`: every call would make a new Custom node |
| `Function` bodies that call one another in a cycle | `DSH6260`: their bodies are embedded in one Custom node |
| `ShaderFunction` blocks of one file that call one another in a cycle | `DSH8299` |
| Nested calls in one expression | legal — arguments are ordinary expressions, so `F(G(x), 2.0)` works for any callable kind |
| A call used as an `Outputs` binding expression | legal — bindings are full expressions |

## Which calls are reused

Since <Since v="2.0.0" /> reuse is one deduplication pass over the whole graph: two nodes with the same
class and the same arguments are one node, for **every** kind of call — the Custom node of a `Function` /
`GraphFunction`, a material function call, the 1.x sugar builtins such as `UE.TexCoord`,
`UE.CollectionParam`, `StaticSwitchParameter` calls, a `UE.Expression` of a Custom class. 1.x made a new
node per call site for most of these.

| Written | Result |
| :-- | :-- |
| `F_Tint(a, b)` twice | one node |
| `F_Tint(a, b)` and `F_Tint(b, a)` | two nodes — the operands differ |
| `F_Tint(a, b)` and `F_Tint(Color = a, Tint = b)` | one node — they build the same node |
| `F_Tint(Color = a)` and `F_Tint(color = a)` | one node — the other case is the same declaration (`DSH5275`) |
| `UE.TexCoord(Index = 0)` and `UE.TexCoord(Index = 1)` | two nodes — a property differs |
| a parameter's pin call and a bare read of it | two nodes — the arguments differ |

`Outputs` expression targets (`Expression( … ).Pin[i]` and the block form) are grouped not by this pass
but while the `Outputs` section is read, by class and argument list: one extra or missing argument
silently makes a second node. See [Output Bindings](/en/docs/generation/outputs).

  <D msg="DSH6314: Expected a ')' to close the 'UE.' call in the body of '{0}', found the end of the body." cause="A UE. call in a GraphFunction body has no closing )." />
  <D msg="DSH5259: Expected every argument of the parameter call '{0}' to name an input pin, found a positional argument." cause="A positional argument in a parameter pin call." fix="Name each argument: MyTex(Coordinates = uv)." />
  <D msg="DSH5214: {0} expects {1}, and this is {2}." cause="A value does not fit the pin it feeds." />
  <D msg="DSH5213: '{0}.{1}' has no pin or property called '{2}'." cause="A name that is neither a pin nor a property, with a value that is not a graph value — usually an asset slot passed as a call argument." href="/en/docs/parameters/metadata" />
  <D msg="DSH5258: Expected the static switch '{0}' to be called with a 'True = ...' and a 'False = ...' input, found at most one of them." cause="A StaticSwitchParameter call without both branches." fix="Pass True = ... and False = ...." />
  <D msg="DSH5254: '{0}' takes no positional argument here; 1.x ignored it, so it is dropped." cause="Warning: an argument a 1.x call spelling never read is dropped." fix="Name the argument the way the spelling reads it, or delete it." />
</Diag>

## Example

```c
import "Helpers.dsh";

Shader(Name="Docs/M_Calls")
{
    Properties {
        vec3                     Tint    = vec3(1.0, 0.4, 0.1);
        TextureSampleParameter2D Albedo  = Path(Game, "Textures/T_Albedo");
        StaticSwitchParameter    UseTint = true;
    }

    Settings {
        Domain       = "Surface";
        ShadingModel = "Unlit";
    }

    Outputs {
        vec3 Color;
        Base.EmissiveColor = Color;
    }

    Graph {
        vec2 UV  = UE.TexCoord(Index = 0);

        // Parameter pin call: wires the sampler's Coordinates pin, read through RGBA.
        vec4 Tex = Albedo(Coordinates = UV);

        // Value form, a Function with a return value, declared in Helpers.dsh.
        float L  = Luma(Tex.rgb);

        // Value form, namespaced Function: the value is its first out parameter.
        vec3 Lit = Common::ApplyTint(Tex.rgb, Tint);

        // Statement form: inputs first, then one out target per output. Neither target is
        // declared, so each becomes a local of its output's type (info DSH5283).
        PulseTint(Lit, Tint, Pulsed, Amount);

        // StaticSwitchParameter call selects between the two.
        Color = UseTint(True = Pulsed, False = vec3(L, L, L));
    }
}
```

`Helpers.dsh`:

```c
Function float Luma(in vec3 color) { return dot(color, float3(0.299, 0.587, 0.114)); }

Function PulseTint(in vec3 color, in vec3 tint, out vec3 result, out float amount) {
    amount = 0.5 + 0.5 * sin(color.r * 6.28318);
    result = color * tint * amount;
}

Namespace(Name="Common")
{
    Function ApplyTint(in vec3 color, in vec3 tint, out vec3 result) {
        result = color * tint;
    }
}
```

```text
TextureCoordinate                      -> UV
TextureSampleParameter2D  Albedo       -> Tex          (Coordinates pin wired to UV)
Custom  "Luma"                         -> L
Custom  "Common::ApplyTint"            -> Lit
Custom  "PulseTint"                    -> Pulsed (output result), Amount (output amount)
AppendVector, AppendVector             -> vec3(L, L, L)
StaticSwitchParameter  UseTint         -> Color
```

The `PulseTint` Custom node's outputs are named after the function's `out` parameters — `result` is output
0 and `amount` an additional output <Since v="2.0.0" /> (1.x named the additional outputs after the
**caller's** out variables).
