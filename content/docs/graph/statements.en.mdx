---
title: Statements
description: Every statement form a Graph body can contain — declarations, assignments, member writes, calls — plus termination, classification, MaterialAttributes and scope.
---

A `Graph` body is a sequence of statements. There are ten forms, and every one except `if` ends with
`;`. Since <Since v="2.0.0" /> the body is read token by token by the 2.0 statement parser instead of
being split as text at `;`; a construct 1.x did not have is recognised and refused with a code, rather
than misread as a declaration with a bad type.

## Synopsis

<Synopsis>
```c
graph-statement :=
      <type> <name> [ = <expression> ] ;                          // declaration
    | <type> <name> [ = <init> ] , <name> [ = <init> ] … ;        // comma declarators
    | <type> <name> = { <expression> , … } ;                      // brace initializer
    | <name> = <expression> ;                                     // assignment
    | <name> . <member> = <expression> ;                          // member write
    | <call-expression> ;                                         // statement-form call
    | if ( <condition> ) { <graph-statement> … }
      [ else { <graph-statement> … } | else if ( … ) { … } … ]
```
</Synopsis>

<Grammar />

## The ten forms

| # | Form | Example | Terminator |
| --: | :-- | :-- | :-- |
| 1 | Declaration, no initializer | `float3 c;` | `;` |
| 2 | Declaration + expression initializer | `float3 c = A * K;` | `;` |
| 3 | Declaration + brace initializer | `vec4 v = {rgb, 1.0};` | `;` |
| 4 | Assignment to an existing or output variable | `Color = Tint;` | `;` |
| 5 | Assignment + brace initializer | `Color = {r, g, b};` | **refused** — `DSH2162` <Since v="2.0.0" />; write `Color = float3(r, g, b);` |
| 6 | `MaterialAttributes` member write | `Attrs.BaseColor = Tint;` | `;` |
| 7 | Member write + brace initializer | `Attrs.BaseColor = {1, 0, 0};` | **refused** — `DSH2162` <Since v="2.0.0" />; write a constructor |
| 8 | Comma-separated declarators | `float a = 1, b, c = 3;` | `;` |
| 9 | Statement-form call | `F_Split(Src, OutA, OutB);` | `;` |
| 10 | `if` / `else` / `else if` | `if (m > .5) { … } else { … }` | none — ends at the `}` of its last body |

Form 8 expands to one variable per declarator. All of them share the type token of the **first**
declarator, and each reports its own line and column.

## Termination and splitting

| Rule | Behaviour |
| :-- | :-- |
| Separator | every statement except `if` ends with `;`; a missing one is `DSH2154`, reported at the first token after the statement |
| Repeated `;` | each extra `;` is an empty statement and is dropped without a diagnostic |
| Final `;` | **required** on the last statement of a body too: `DSH2154` <Since v="2.0.0" /> |
| `if` statements | end with the `}` of their last body, so an `if` needs no `;` |
| Positions | every statement and expression carries its own line and column |
| Nested bodies | `if` / `else` bodies are blocks of the same grammar, so **every** form above is legal inside a branch, including nested `if` |

```c
Graph = {
    float a = 1.0;;;             // the empty statements are dropped
    if (a > 0.5) { a = 0.0; }    // no ; after the }
    float b = a * 2.0;           // the final statement needs its ; (DSH2154 without it)
}
```

A statement that fails to parse is skipped up to the next `;` at its own nesting level, and the parser
carries on with the next one; every error of the body is reported in one build.

## Classification order

The parser decides a statement's form from its first tokens. The first rule that matches wins.

| Order | Statement starts with | Result |
| --: | :-- | :-- |
| 1 | the keyword `if` (**case-sensitive**) | form 10 |
| 2 | `for`, `while`, `do`, `return`, `break`, `continue`, `discard` | parsed, then refused: `DSH2208` |
| 3 | `switch`, `case`, `default` | `DSH2160` |
| 4 | `{` | a bare block: `DSH2220` |
| 5 | `;` | an empty statement |
| 6 | a `#Region` / `#EndRegion` line | a region; see [Layout and #Region](/en/docs/language/layout) |
| 7 | two names in a row (`float3 c`), optionally after `static` / `const` | a declaration: forms 1–3 and 8. A storage keyword is `DSH2212` |
| 8 | anything else | an expression: an assignment (forms 4–7), a call (form 9), or `DSH2211` for a value nothing receives |

<Callout type="warn">
Keywords are case-sensitive. `If (x) { … }` is not an `if` statement: `If` is a name, `If (x)` a call,
and the `{` where the call statement's `;` belongs is `DSH2154`. See
[What Graph Is Not](/en/docs/graph/unsupported#wrong-case-keywords).
</Callout>

<Callout type="info">
A declared name is one identifier. `float3 A.B = x;` is `DSH2154` at the `.` <Since v="2.0.0" />; 1.x
declared a variable literally named `A.B`. A member write has no type in front: `Attrs.BaseColor = x;`.
</Callout>

## Declarations

<Synopsis>
```c
<type> <name> [ = { <expression> | <brace-initializer> } ]
     [ , <name> [ = { <expression> | <brace-initializer> } ] ] … ;

brace-initializer := { [ <expression> [ , <expression> ] … ] }
```
</Synopsis>

### Accepted type tokens

| Token | Components | Notes |
| :-- | --: | :-- |
| `float` `float1` `half` `half1` `int` `uint` `bool` | 1 | |
| `float2` `half2` `vec2` `int2` `uint2` `bool2` `ivec2` `uvec2` `bvec2` | 2 | |
| `float3` `half3` `vec3` `int3` `uint3` `bool3` `ivec3` `uvec3` `bvec3` | 3 | |
| `float4` `half4` `vec4` `int4` `uint4` `bool4` `ivec4` `uvec4` `bvec4` | 4 | |
| `MaterialAttributes` | — | see [below](#materialattributes-member-writes) |
| `Substrate` | — | <Since v="5.4" ue /> requires an initializer |
| `StaticBool` `StaticBoolParameter` | 1 | a `bool` variable <Since v="1.6.0" /> |
| `Texture2D` | — | requires an initializer |
| `TextureCube` | — | requires an initializer |
| `Texture2DArray` | — | requires an initializer |
| `Texture3D` `VolumeTexture` | — | requires an initializer |
| `SamplerState` | — | a sampler of its own, no longer a `Texture2D` <Since v="2.0.0" />; requires an initializer |

Every row is matched case-insensitively (`Float3`, `VEC3`, `materialattributes`). A type token is
**one** token <Since v="2.0.0" />: `float 3` and `Material Attributes` no longer read as types. `vec*`,
`ivec*`, `uvec*` and `bvec*` read as `float*`, `int*`, `uint*` and `bool*`.

`int`, `uint`, `bool` and `half` are kinds of their own to the compiler — a `/` between two integer
constructors is `DSH4243`, a condition is a `bool` — and every one of them is a float in the generated
graph. The matrix spellings (`mat3`, `float3x3`) resolve, but the graph has no matrix values:
`DSH4361`. The full catalogue is on [Types and Values](/en/docs/language/types-and-values).

### Declarations without an initializer

1.x read an unset variable as zero, so the legacy front end gives `<type> <name>;` an initializer:

| Declared type | Initializer |
| :-- | :-- |
| scalar (1 component) | `0` (`false` for a `bool`) |
| vector (2–4 components) | `floatN(0, …)` — one zero per component, in the declared kind |
| `MaterialAttributes` | an empty attribute set (`MakeMaterialAttributes`) |
| `Substrate` | none — `DSH2215` |
| any texture type, `SamplerState` | none — `DSH2215` |
| a token that does not resolve | `DSH4201` |

```c
float3 c;              // float3(0, 0, 0)
MaterialAttributes A;  // an empty set, ready for member writes
Texture2D T;           // DSH2215: requires an initializer
```

### Declarations with an initializer

The initializer is evaluated, then converted to the declared type:

| Order | Step |
| --: | :-- |
| 1 | the type token must resolve, else `DSH4201` |
| 2 | a scalar spreads to every component of a vector type |
| 3 | a wider vector gives its **leading** components — legacy rule L22, said by the info `DSH5289` |
| 4 | anything else that does not fit — a narrower vector, a texture into a number — is `DSH4228` |

Step 4 means a 2-component value never widens to 3. See
[Conversions](/en/docs/graph/expressions#conversions).

<Callout type="warn">
**Authoritative widths no longer override the declared width** <Since v="2.0.0" />. 1.x let certain
values (`UE.TexCoord`, `UE.CameraVectorWS`, a constant-folded constructor, `dot`, …) keep their own
width whatever the declaration said, so `float2 dir = UE.CameraVectorWS();` made `dir` three components
without a message. Now the declared type is the variable's type: `dir` is a `float2`, the leading two
components of the value, with `DSH5289`. A 1.x source that relied on the override builds a different
graph than it did through 1.9.x, and nothing reports it — rebuild such a material and check it.
</Callout>

### Comma declarators

```c
float a = 1, b, c = 3;
```

| Rule | Behaviour |
| :-- | :-- |
| Recognition | a declaration whose declarator is followed by `,` and another name |
| Shared type | every declarator has the type of the **first**; a type token after a `,` is read as the next declarator's name, and what follows it is `DSH2154` |
| Declarator names | must be identifiers, else `DSH2163` |
| Initializers | each declarator may carry its own `= <expression>` or `= { … }`, or none |
| Source location | each declarator reports its own line and column <Since v="2.0.0" /> |

The example declares three 1-component values: `a` initialized to `1`, `b` to `0`, `c` to `3`.

### Brace initializers

A brace list as the initializer of a declaration is rewritten to a constructor call of the declared
type: `T x = { a, b };` is `T x = T(a, b);`. It is therefore **exactly** a constructor call and
inherits every rule of [Constructors](/en/docs/graph/expressions#constructors): positional arguments
only (`DSH4225`), a single scalar spreads to every component, and several arguments must add up to
exactly the type's width (`DSH4222`).

`{}` is special-cased: it is no initializer at all, so the variable gets the zero of its type.

The target type is always the declared type token. A brace list anywhere else — on the right of an
assignment or a member write, as an argument — is `DSH2162` <Since v="2.0.0" />. A texture, `Substrate`
or `MaterialAttributes` type has no constructor: `Texture2D t = {x};` is `DSH4223`.

<Callout type="warn">
Nested braces do not work. `float4 m = {{1,2},{3,4}};` is `DSH2214`; write
`float4(float2(1, 2), float2(3, 4))`.
</Callout>

```c
Graph = {
    float r = 1.0;
    float g = 0.5;
    float b = 0.2;
    vec3 rgb  = {r, g, b};      // -> vec3(r, g, b)
    vec4 rgba = {rgb, 1.0};     // -> vec4(rgb, 1.0), mixed-width packing
    Color = rgba.rgb;
}
```

### Redeclaration

A declaration whose name is already declared in the same block is `DSH4220`. So is a declaration
inside an `if` or `else` body of a name the enclosing body already declares, and, in a `Shader`, a
declaration named `Base`, which is the material itself.

The check compares names **exactly** <Since v="2.0.0" />: `float a = 1; float A = 2;` declares two
variables, where 1.x reported a redeclaration. A read of `a` or `A` finds its own variable; a read in a
case that matches neither exactly finds a unique case-insensitive match, with the warning `DSH5275`.

Assignment to an existing name is not a redeclaration — omit the type token to reassign.

## Assignment

Forms 4 and 6. The target is a name or `name.member`; anything else — a swizzle of a member, an index,
a call — is `DSH2206`.

<Synopsis>
```c
<target> = <expression> ;
```
</Synopsis>

The target is resolved in this order:

| Order | Target | Behaviour |
| --: | :-- | :-- |
| 1 | `name.member` | `MaterialAttributes` member write — see [below](#materialattributes-member-writes) |
| 2 | a Graph variable, an `Outputs` declaration of a `Shader`, or an output of a function block | the value is converted to the variable's declared type |
| 3 | a property | `DSH4229`: a property is an input; copy it into a variable first |
| 4 | nothing | declared here, with the value's type — legacy rule L26, said by the info `DSH5292` |

A name is looked up exactly first, then ignoring case; a unique match in another case is taken with
the warning `DSH5275` — it **is** that declaration, not a second variable <Since v="2.0.0" />.

Rule 4 means an undeclared name on the left of `=` is not an error:

```c
Graph = {
    vec3 Boost = Tint * 2.0;
    Scratch    = Boost;      // DSH5292: declares 'Scratch' as a float3
    Color      = Scratch;    // 'Color' is an Outputs declaration -> converted to its type
}
```

The conversion at rule 2 takes the **leading components** of a wider value, with the info `DSH5289`
(legacy rule L22), and spreads a scalar across a wider target. It never widens a 2-component value to
3: that, and any other value that does not fit, is `DSH4228`. See
[Conversions](/en/docs/graph/expressions#conversions).

## Expression statements

Form 9. A statement that is neither a declaration nor an assignment must be a **call**; any other
expression is `DSH2211`.

In statement form a function's outputs are received by the trailing arguments, one variable per
output, in declaration order. A statement may call anything: a call whose value nothing receives — a
builtin, a constructor, a parameter — is accepted, and its node is pruned because nothing reads it
<Since v="2.0.0" />. Full argument rules, out-target constraints and the value form are on
[Calls](/en/docs/graph/calls).

Multi-output `ShaderFunction` / `VirtualFunction` statement calls are available since
<Since v="1.3.5" />; single-output `Function` / `GraphFunction` value calls since <Since v="1.3.1" />.

## `MaterialAttributes` member writes

Form 6 writes one attribute of a `MaterialAttributes` value — a struct-like Graph value
<Since v="1.2.5" /> that carries a whole material's attribute set as one connection. It is a type of its
own, never a scalar or a vector: arithmetic on it and passing it to a constructor are `DSH4226`, and it
can only be assigned from another `MaterialAttributes` value — anything else is `DSH4228`.

| Form | Effect |
| :-- | :-- |
| `MaterialAttributes Attrs;` | an empty set: one `MakeMaterialAttributes` with every input unconnected. Unlike `Texture2D` and `Substrate`, it does **not** require an initializer |
| `MaterialAttributes Attrs = {};` | identical to the line above |
| `MaterialAttributes B = A;` | `B` takes `A`'s value; no node is created. It is a value copy, not an alias: a later `B.Roughness = r;` changes `B` only |
| `MaterialAttributes Attrs = F_Layer(uv);` | any expression whose value is a `MaterialAttributes` — a function call, a `StaticSwitchParameter` call |

<Callout type="warn">
**In a `Shader`, an `Outputs` declaration creates the variable** <Since v="2.0.0" />. Every `Outputs`
declaration is declared at the top of the material's body, and a `MaterialAttributes` one starts as an
empty set, so `Attrs.BaseColor = Tint;` works with no `Graph` declaration at all. A
`MaterialAttributes Attrs;` in the `Graph` names that same variable and adds nothing. In a function
block a `MaterialAttributes` output is the function's output: the attributes written to it make its
set, and reading one never written is `DSH4370`.

```c
Outputs = { MaterialAttributes Attrs; Base.MaterialAttributes = Attrs; }
Graph   = { Attrs.BaseColor = Tint; Attrs.Roughness = 0.35; }
```
</Callout>

### Members

The attribute table is the engine's <Since v="2.0.0" />: an attribute this engine does not have is
`DSH5200`. A member name is matched exactly first (name or alias), then ignoring case, with the warning
`DSH5276`. Aliases are exact synonyms.

| Member | Aliases | Components |
| :-- | :-- | :-- |
| `BaseColor` | — | 3 |
| `Metallic` | — | 1 |
| `Specular` | — | 1 |
| `Roughness` | — | 1 |
| `Anisotropy` | — | 1 |
| `EmissiveColor` | `Emissive` | 3 |
| `Opacity` | — | 1 |
| `OpacityMask` | — | 1 |
| `Normal` | — | 3 |
| `Tangent` | — | 3 |
| `WorldPositionOffset` | `WPO` | 3 |
| `SubsurfaceColor` | — | 3 |
| `CustomData0` | `ClearCoat` | 1 |
| `CustomData1` | `ClearCoatRoughness` | 1 |
| `AmbientOcclusion` | `AO` | 1 |
| `Refraction` | — | 3 |
| `CustomizedUV0` … `CustomizedUV7` | — | 2 |
| `PixelDepthOffset` | `PDO` | 1 |
| `Displacement` | — | 1 |
| `DiffuseColor` | — | 3 |
| `SpecularColor` | — | 3 |
| `SurfaceThickness` | — | 1 |
| `FrontMaterial` <Since v="5.4" ue /> | — | a `Substrate` value <Since v="2.0.0" /> |
| `MaterialAttributes` | `Attributes` | the whole set |

The 1.x aliases `CustomizedUVs0` … `CustomizedUVs7` are not in the alias table <Since v="2.0.0" />;
write `CustomizedUV0` … `CustomizedUV7`. `MaterialAttributes` (alias `Attributes`) resolves as a member
<Since v="2.0.0" />: it is the whole set, and it is what the binding `Base.MaterialAttributes = Attrs;`
writes. To replace a Graph variable's whole set, assign the variable itself: `Attrs = Other;`.

### Reading a member

A read of an attribute the body has already written in this value is that written value; no node is
made. Any other read comes from one `BreakMaterialAttributes` per value, shared by all of that value's
reads <Since v="2.0.0" /> (1.x made one Break node per read). A read that has to go through the Break
node needs the engine's Break node to publish the attribute, otherwise it is `DSH8216` — this depends on
the engine build. A value with nothing to read from — a function's `MaterialAttributes` output before
anything was written to it — is `DSH4370`.

The read result is a plain numeric value with the member's component count, so it may be swizzled:
`Attrs.BaseColor.r` is an attribute read followed by a channel selection.

### Writing a member

A member write records the value for that attribute; a later write of the same attribute replaces it.
Nodes are made where the value is **used** — passed to a function or a pin, assigned to an output,
bound to the material: one `SetMaterialAttributes` on top of the value's set, with one pin per attribute
written so far <Since v="2.0.0" /> (1.x chained one Set node per write). A value with no set underneath —
a function's output — becomes one `MakeMaterialAttributes` with the written pins instead.

| Rule | Code when it fails |
| :-- | :-- |
| The target is `name.member`; a member of a member is not a target | `DSH2206` |
| The base name must be declared | `DSH4200` |
| The base must hold a `MaterialAttributes` value | on a number the member is read as a swizzle, `DSH4230`; on a texture `DSH4206`; on a `Substrate` value `DSH4207` |
| The member name must resolve | `DSH5200` |
| The value must fit the member's type | `DSH4228`; a wider vector gives its leading components with the info `DSH5289` |

<Callout type="info">
`Attrs.BaseColor.r = 1.0;` is `DSH2206`. There is no per-channel attribute write in a 1.x Graph; build
the full value first. `Attrs.BaseColor = {1.0, 0.35, 0.1};` is `DSH2162` <Since v="2.0.0" />: write
`Attrs.BaseColor = float3(1.0, 0.35, 0.1);`.
</Callout>

### Passing attribute values around

| Context | Behaviour |
| :-- | :-- |
| `Base.MaterialAttributes = Attrs;` | binds the value to the material and turns *Use Material Attributes* on |
| `ShaderFunction` / `ShaderLayer` / `ShaderLayerBlend` / `VirtualFunction` inputs and outputs | accepted. The argument must already be a `MaterialAttributes` value; nothing is converted (`DSH4226` for an input, `DSH4218` for an output variable of another type) |
| `GraphFunction` result type | accepted |
| `if` / `else` | merged attribute by attribute: one conditional node per attribute the branches disagree on. A different **whole** set in the two branches is `DSH4375` — see [Control Flow](/en/docs/graph/control-flow#what-cannot-be-selected) |
| `StaticSwitchParameter` call branches | accepted when both branches are attribute values |

`Substrate` is a separate value type, not an attribute set, and requires UE 5.4+; the two never convert
into each other (`DSH4228`). `Attrs.FrontMaterial` resolves on UE 5.4+ and is typed **`Substrate`**
<Since v="2.0.0" /> (1.x typed it as one number). Binding both `Base.MaterialAttributes` and
`Base.FrontMaterial` in one `Shader` is no longer refused <Since v="2.0.0" />: both are wired, and the
*Use Material Attributes* flag the first one turns on makes the material read the attribute set rather
than its individual pins. See [Substrate](/en/docs/builtins/substrate).

## Scope

Each `if` and `else` body is a block with a scope of its own <Since v="2.0.0" />; 1.x had one value
table for the whole body.

| Situation | Outcome |
| :-- | :-- |
| Declaration at body level | visible for the rest of the body. In a `Shader` that body also holds the `Outputs` declarations, before the `Graph` statements |
| Declared **before** the `if`, assigned in a branch | the two values merge into one conditional node, and the variable holds the merged value after the `if` |
| Declared **inside** a branch | dropped when the branch ends; nothing is merged, and a read after the `if` is `DSH4200` |
| A branch declares a name the enclosing body already declares | `DSH4220` |
| A property read inside a branch | a property is a file-scope input, never a branch value |

<Callout type="warn">
1.x merged a name declared in both branches and let it be read after the `if`. That name is now
branch-local. Declare the variable **before** the `if` and assign it in each branch:

```c
float3 Blend = float3(0.0, 0.0, 0.0);
if (Mask > 0.5) { Blend = float3(1.0, 0.0, 0.0); }
else            { Blend = float3(0.25, 0.25, 0.25); }
Color = Blend;
```

A branch-local name may be declared again after the `if`: its scope has ended. The full merge rules
are on [Control Flow](/en/docs/graph/control-flow#the-merge).
</Callout>

## Synthesized statements

Every `Outputs` declaration of a `Shader` becomes a variable declared at the top of the material's
body, before the first `Graph` statement <Since v="2.0.0" />. It is initialized with its own initializer
when it has one, and otherwise with a zero of its type (an empty set for `MaterialAttributes`); a
texture or `Substrate` output without an initializer starts without a value. These declarations carry
the position of the `Outputs` line they came from.

A top-level `Graph` declaration of an output's name (same case) does not declare a second variable:
with an initializer it becomes an assignment to the output, and without one it is dropped.

| Code | Raised when |
| :-- | :-- |
| `DSH3270` | an `Outputs` declaration has `=` and nothing after it |
| `DSH3266` | an `Outputs` declaration is followed by neither `;` nor the section's closing `}` |

A `Shader` whose `Outputs` section declares or binds anything needs no `Graph` section; one with
neither is `DSH2255`. See [Output Bindings](/en/docs/generation/outputs).

## Example

Every accepted statement form in one body:

```c
ShaderFunction(Name="Functions/F_AllForms")
{
    Properties = { vec3 Tint = vec3(1.0, 0.4, 0.1); float K = 2.0; }
    Inputs     = { vec2 UV; }
    Outputs    = { MaterialAttributes Attrs; vec3 Debug; }

    Graph = {
        MaterialAttributes Attrs;              //    names the output: no second variable
        float3 c;                              // 1  declaration, no initializer
        float3 scaled = Tint * K;              // 2  declaration + expression
        vec4   packed = {scaled, 1.0};         // 3  declaration + brace initializer
        c = packed.rgb;                        // 4  assignment
        Debug = float3(0.0, 0.0, 0.0);         //    (form 5 is refused: write the constructor)
        Attrs.BaseColor = c;                   // 6  member write
        Attrs.Roughness = 0.35;                //    (form 7 is refused: write the value)
        float a = 1, b, d = 3;                 // 8  comma declarators

        if (K > 1.0) {                         // 10 if / else
            Debug = c * a;
        } else {
            Debug = c * b;
        }
    }
}
```

The only form missing is 9, the statement-form call — it needs a callee, so it has its own page.
