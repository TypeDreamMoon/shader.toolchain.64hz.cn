DreamShaderLang is a text language for Unreal Engine materials. You write source files; the **DreamShader** plugin
compiles them inside the editor and builds standard Unreal assets — `UMaterial`, `UMaterialFunction`,
`UMaterialFunctionMaterialLayer`, `UMaterialFunctionMaterialLayerBlend` and `UMaterialInstanceConstant` — and, on
Unreal Engine 5.8, `.dsp` [Custom Pass](#custom-pass) pipelines into `UDreamPassPipeline` assets that add render passes
of your own.

The source file is the authoring surface. The asset is build output, and can always be thrown away and regenerated.

Two syntaxes, one compiler <Since v="2.0.0" />: write new sources as `.dss` — HLSL with declarations — and `.dsi`
material instances, see [DreamShaderLang 2.0](/en/docs/language-v2); the 1.x `.dsm` / `.dsf` / `.dsh` keep compiling,
the Language and Graph sections describe that syntax, and [`dsc migrate`](/en/docs/language-v2/migrate) rewrites them
as `.dss` one file at a time.

## Six kinds of source file

| Extension | What it is | Generates |
| --- | --- | --- |
| `.dss` | a DreamShaderLang 2.0 compilation unit: `uniform`s, `#pragma material`, `export` functions | one asset per `export` — a material, or a set of material functions / layers / blends |
| `.dsi` | a material instance: the parent and the overrides | one `UMaterialInstanceConstant` |
| `.dsp` | a Custom Pass pipeline: buffers and an ordered list of passes (UE 5.8) | one `UDreamPassPipeline` |
| `.dsm` | a 1.x material: at most one `Shader`, plus function, layer, namespace and VirtualFunction blocks | the material, plus every function asset declared in the same file |
| `.dsf` | a 1.x function file: `ShaderFunction`, `ShaderLayer`, `ShaderLayerBlend` and helper blocks, no `Shader` | the function assets it declares |
| `.dsh` | a header: helpers, `VirtualFunction` / `extern` declarations; holds both dialects | no asset of its own; consumed through `import` / `#include` |

Each file is parsed on its own; an imported header is parsed on its own too, and its declarations become names of the
file that imports it <Since v="2.0.0" />. See [File model](/en/docs/language/file-model) and
[Project layout](/en/docs/start/project-layout).

## What each block generates

| `.dss` | 1.x block | Unreal asset |
| --- | --- | --- |
| `export void M(inout material m)` | `Shader` | `UDreamShaderMaterialInstance` plus a hidden `UMaterial` base (`ThinCustom`, the default), or a plain `UMaterial` (`Graph` backend) |
| any other `export` function | `ShaderFunction` | `UMaterialFunction` |
| an `export` with `/// @layer` / `/// @layerblend` | `ShaderLayer` / `ShaderLayerBlend` | `UMaterialFunctionMaterialLayer` / `UMaterialFunctionMaterialLayerBlend` |
| an `extern` prototype with `/// @asset` | `VirtualFunction` | no asset — declares an existing `UMaterialFunction` so a material can call it |
| a `/// @custom` function | `Function` / `GraphFunction` | `Custom` node code |
| `.dsi` | — | `UMaterialInstanceConstant` |

## A minimal material

```hlsl
// DShader/Materials/M_Minimal.dss
#pragma material(Domain = UI, ShadingModel = Unlit)

uniform float3 Tint = float3(1.0, 0.2, 0.2);

export void M_Minimal(inout material m)
{
    m.EmissiveColor = Tint;
}
```

The same material in 1.x syntax:

```c
// DShader/Materials/M_Minimal.dsm
Shader(Name="Materials/M_Minimal")
{
    Properties = {
        vec3 Tint = vec3(1.0, 0.2, 0.2);
    }

    Settings = {
        Domain = "UI";
        ShadingModel = "Unlit";
    }

    Outputs = {
        vec3 Color;
        Base.EmissiveColor = Color;
    }

    Graph = {
        Color = Tint;
    }
}
```

Both files build `/Game/Materials/M_Minimal` — keep one.

<Callout type="info">
  Under the default `ThinCustom` backend the generated material is **Ephemeral** — it lives in memory only and does not
  appear in the Content Browser. This is deliberate, and there are three ways to find it — see
  [Your first material](/en/docs/start/first-material).
</Callout>

## Custom Pass

<Since v="2.1.0" />

On Unreal Engine 5.8, a [`.dsp` pipeline](/en/docs/language-v2/passes) adds render passes of your own without touching
the engine: a mask of selected objects, a blur, a screen-space effect, a compute shader writing a data texture. Its
passes run at the injection points they choose — before the base pass, after the opaque lighting, before or inside the
post-process chain — as Post Process materials, project HLSL, or selected meshes drawn again; their buffers can be read
by any material.

## What DreamShader does and does not do

It generates material assets inside the Unreal Editor, and that is its whole scope. Specifically:

- **A 1.x `Graph` is a node-graph builder, not a shader compiler.** It has four arithmetic operators and `if` / `else`:
  no loops, no ternary, no `%`, no comparisons or bitwise operators outside an `if` condition, no matrices, no indexing,
  no compound assignment. <Since v="2.0.0" /> Each of these is an error with a code, not a silent truncation — see
  [Unsupported constructs](/en/docs/graph/unsupported). A `.dss` has loops and the full operator set; genuinely
  imperative code belongs in a `/// @custom` function or a 1.x `Function`, whose body is real HLSL.
- **Generation happens in the editor only.** There is no runtime path that builds a material from DreamShaderLang, and
  the tools do not exist in a packaged game; the one runtime part is the Custom Pass module that runs compiled
  pipelines.
- **Generated assets are products, not documents.** Regeneration tears the graph down and rebuilds it, so manual edits
  are lost; parameter overrides on a generated instance are put back by name. Since <Since v="1.8.0" /> the rebuild that
  would destroy a hand edit **does not happen** — the asset carries a digest, a mismatch refuses the compile, and you
  pick Revert / Adopt / Detach. See [Regeneration](/en/docs/generation/regeneration).
- **`Substrate.*` needs <Since v="5.4" ue />, Custom Pass needs <Since v="5.8" ue />.** The node catalog follows the
  running engine, and what the engine does not have is refused explicitly.
- **Some spellings are deprecated.** `Backend = Instance` and the `MaterialLayer` / `MaterialLayerBlend` block keywords
  — they still work, with a warning.
